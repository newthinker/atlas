# Prism M3.5 数据链路基建设计（数据源扩展 + 降级链 + ETF 聚合）

> 日期: 2026-08-02 | 关联: docs/prism/atlas_prism_design.md §9 M3.5、§10 风险表
> 背景: M3.5 原立项为「Stooq 备源 + ETF 聚合」。本轮 brainstorming 经实测推翻 Stooq 可行性,
> 并按用户决策扩展范围:新增 Tushare 与 Baostock 数据源、降级链按「市场×能力」重组。

## 0. 实测记录（本设计的事实基础，全部 2026-08-02 实测）

| 数据源 | 实测结果 | 结论 |
|--------|---------|------|
| Stooq 逐标的 CSV | 全站 JS 工作量证明反爬墙（SHA-256 PoW 换会话 cookie），直连与代理均被拦 | **出局**——非 IP 拦截非配额，代理无效；headless 浏览器跑 PoW 不值得 |
| Stooq 打包下载（db/h + static zip） | 下载页同一道 PoW 墙；zip 端点 401（需验证后会话） | 同上 |
| Tushare（用户 token） | A 股 daily ✅、index_daily ✅、**daily_basic（pe_ttm/pb/ps_ttm）✅**、hk_daily ✅；us_daily ❌（需 5000 积分）、income ❌（需 2000 积分） | 角色 = **A/H 估值+行情备源**；美股/财务不可用 |
| akshare 新浪美股（stock_us_daily） | NVDA 全历史 5733 行、最新至昨日、经 aktools | 可行，但用户决策选 Twelve Data 转正（本设计记为储备） |
| iShares 持仓 CSV | 旧 ajax 端点返回 HTML 壳（已废） | 出局 |
| SSGA 持仓 | 每日 xlsx 真实文件（22KB） | 可用但仅覆盖 SSGA + 需 xlsx 依赖；用户决策选 N-PORT |
| Baostock | 纯 Python 库、无 HTTP API、本机无现成环境 | 接入必须新建侧车桥（用户决策：本批建桥） |

## 1. 范围与分批

- **M3.5a — 数据源与降级链**：Twelve Data（美股价格备源）、Tushare（A/H 估值+行情备源）、Baostock 桥（A 股行情第三跳）、编排层降级分派与可观测。
- **M3.5b — ETF 成分聚合（D3）**：N-PORT 持仓解析、加权调和平均聚合引擎、首批 11 个 SPDR 行业 ETF。
- 一份 spec、两份实施计划，先 a 后 b（b 计划中 N-PORT 标识映射的 live 校验结论依赖 a 期间的探针）。

## 2. 降级链总表（按「市场×能力」组织）

组织原则（2026-08-02 讨论定案）：默认链按 (市场, 数据能力) 定义；标的级 `fallback_source` 仅作例外覆盖；**相邻两跳必须在上游数据商/网络路径/封禁面至少一层正交**（v1.4.0 双失败教训）；每跳切换经 `Report.Degraded` 上报；每跳声明触发错误类型（临时不可用→下一跳；永久不覆盖→改配置，不得天天降级）。

| 市场×能力 | 主源 | 二跳 | 三跳 | 备注 |
|----------|------|------|------|------|
| 美股·价格 | yahoo | **twelvedata**（新） | （储备：akshare 新浪） | TD 免费 800 次/天，Prism 美股 ~21 标的增量足够 |
| A股公司·估值 | akshare 百度 | **tushare daily_basic**（新） | — | tushare 为官方计算口径 pe_ttm/pb/ps_ttm。**⚠ 容量边界（2026-08-02 断源演练实测）**：`daily_basic` 限频 **1 次/分钟**，而 refresh **串行**遍历标的 ⇒ 单次 refresh 中**只有第一个 A 股标的能真正兜底**（实测 600519 通过额度检查，紧随的 600036/000423 全部 40203 限频）；连续触发后限频窗口**自升级为 1 次/小时**。当前池内 3 个 A 股标的 ⇒ **批量断源时覆盖率仅约 1/3**，该跳只能救个别标的，不构成完整兜底。改善见后续任务「限频感知退避」 |
| A股指数·估值 | lixinger | akshare 乐咕 | **tushare**（已实测 2026-08-02：`index_dailybasic` 40203 无权限，链尾定为**仅价格**，`index_daily` ✅） | |
| A股·行情 | akshare 东财 | tushare daily | **baostock 桥**（新） | **三源已登记为备源；跳序与市场过滤未实现**（见后续任务）——路由层 `orderedCollectors` 走 `registry.GetAll()` 的 map 遍历，顺序不确定且不读 `SupportedMarkets()`，故本表的「二跳/三跳」在行情链路上是**设计意图而非当前行为** |
| 港股·估值 | akshare 百度 | tushare hk_daily（仅价格） | — | |
| A/H·财报科目 | akshare 东财利润表 | — | — | tushare income 无权限，不变 |
| ETF·持仓 | **SEC N-PORT**（新） | 手工 YAML | — | M3.5b |

## 3. M3.5a 组件设计

**`internal/collector/twelvedata`**：REST 客户端（`GET api.twelvedata.com/time_series?symbol=&interval=1day&outputsize=&apikey=`→JSON）。key 入 `collectors.twelvedata.api_key`（runtime config，gitignored，不入仓）；**key 由用户注册**（free tier），缺 key 时该跳静默跳过（Degraded 提示「备源未配置」仅在主源失败时出现）。⚠ live 校验：close 复权口径与 yahoo 对齐（PE 需未复权）。限频：8 req/min、800 req/day——客户端内置 8s 最小间隔节流。

**`internal/collector/tushare`**：POST JSON 客户端（`api.tushare.pro`，`{"api_name","token","params","fields"}` → `{code,data:{fields,items}}`；code!=0 为业务错误）。方法：`FetchDailyBasic`（A 股估值序列）、`FetchIndexDaily`、`FetchHKDaily`、`FetchDaily`。token 入 `collectors.tushare.api_key`（同上不入仓）。限频：基础积分档每分钟约 500 次，增量拉取无压力，但客户端仍带 200ms 节流兜底。

**`scripts/baostock/` 桥 + `internal/collector/baostock`**：仿 aktools 模式——独立 venv（`scripts/baostock/setup.sh` 幂等建 venv + 版本冻结）、极简 HTTP 服务（`bridge.py`：`GET /daily?code=sh.600519&start=&end=` → JSON 数组；仅绑 127.0.0.1:8181）、launchd 常驻 `com.newthinker.atlas.baostock`（KeepAlive）。Go 客户端一个方法 `FetchDaily`。复权参数用不复权（口径与 PE 计算一致）。

**编排层**：prism `Refresh` 的降级分派沿用既有 lixinger→akshare 同构模式扩展；`PrismInstrument.FallbackSource` 支持链（逗号分隔或保持单值+编排层默认链——实现计划里按最小改动定）。所有新跳记 `Report.Degraded`。

## 4. M3.5b 组件设计

**`internal/collector/edgar/nport.go`**：复用 submissions API（已有）定位 ETF 的 NPORT-P filing → 拉取 primary XML → 解析 `invstOrSec` 条目（name/cusip/identifiers/pctVal）。**⚠ 本批最大不确定点：持仓标识以 CUSIP/ISIN 为主，ticker 字段可选**——映射方案（identifiers.ticker 优先 → SEC company_tickers.json 辅助 → 名称匹配兜底）在实施计划首个任务 live 校验后定案；映射不到的持仓计入 excluded_weight。ETF 的 CIK：11 个 SPDR sector ETF 同属 SPDR 系列信托（series/class 结构，NPORT 按 series 报）——series id 定位方式同属 live 校验点。

**`internal/prism/aggregate`**：每日对配置的 ETF：最新持仓 → 逐成分当前 PE（优先库内 `valuation_daily` 当日值；未覆盖成分走 yahoo quote 的 trailingPE，⚠ 字段可用性 live 校验）→ **加权调和平均**（D3 口径：剔除 EPS≤0 与 PE 不可得成分，权重重归一，`excluded_weight` 记录，>15% 卡片 ⚠）→ upsert `valuation_daily`（source='aggregate'）。**逐日积累，不做历史回算**（用户决策；积累满 1 年后才有滚动分位）。

**存储**：`etf_holdings` 表启用（设计 §6 既有 schema：etf_id/snap_date/holdings JSON）+ 11 个 SPDR ETF 入 instruments（type=etf, source=aggregate）。

## 5. 风险与对策（并入设计文档 §10）

| 风险 | 对策 |
|------|------|
| Stooq 全站 PoW 反爬（实测记录） | 已出局；记录防止未来重新踩坑 |
| Twelve Data 800 次/天不适用于 ETF 成分股场景（~500 只） | 成分股价格/PE 不走 TD；TD 仅服务 Prism 标的池美股备源 |
| tushare 积分边界（美股/财务/指数估值权限） | 能力面以实测为准；index_dailybasic 已实测 40203 无权限（2026-08-02，TASK-001 探针），指数链尾降为仅价格备源 |
| N-PORT 标识映射（CUSIP→ticker） | 实施首任务 live 校验；映射失败计入 excluded_weight 不阻塞 |
| N-PORT 滞后 ~2 月 | D3「权重漂移可接受」语义内；holdings 表记 snap_date 供审计 |
| baostock 桥成为新常驻服务 | 仿 aktools 成熟模式（venv 隔离/launchd/日志）；失败仅影响 A 股行情第三跳 |
| 密钥管理（tushare token / TD key） | 只入 runtime `configs/config.yaml`（gitignored）；不入 example、不入 plist、不入日志 |

## 6. 验收概要

- M3.5a：人为断 yahoo（错误 base）→ 美股标的经 TD 恢复且 Degraded 上报；断 akshare → A 股估值经 tushare 恢复；三源客户端单测全绿；密钥不出现在任何已提交文件。
- M3.5b：11 个 SPDR ETF 卡片上线，XLK 聚合 PE 与市面数字同量级（口径差异 footnote），excluded_weight 展示正确；N-PORT 月更任务落 etf_holdings。
