## 8. 回答 Leader：「语料输出逐字节不变」能不能当纯测试轮次的通用判据

**能，但它是必要非充分的，必须与一条不依赖语料的结构判据配对使用。**

**它强在哪**（我同意 Leader 的判断）：它把「实现未变」从**声明**变成了**观察**。逐行解释 diff 是在请人相信一段推理；四份输出 sha256 相同是一个谁都能重跑的观察。而且它顺带把「确定性」也一并证了（两端各 2 轮自比）。

**它的盲区**（这一条我建议一并写进索引，否则这个判据会被当成充分条件）：

> **它只覆盖语料实际走到的代码路径。** 改了一条本语料触发不到的分支（错误路径、只对某类未入语料的报告生效的模板、配置分支），输出照样逐字节相同 —— **判据为真，而实现确实变了**。
> 另外它也不区分「没改代码」与「做了保行为的重构」，而本轮要证的恰恰是前者。

**配对方案**（本轮我实际采用的）：加一条**结构**判据 ——

```bash
git show <sha>:internal/hestia/profiles.go | grep -vE '^\s*//' | shasum -a 256
# 两个 commit 应同值；本轮实测同为 ed3760f7d7ac…47ff1
```

两者**互补而非冗余**：
- 结构判据证明「代码部分没改」，且**不依赖语料覆盖率**；
- 行为判据兜住结构判据的过滤器本身可能出错（例如字符串字面量里含 `//` 会被我的 `grep -v` 误删，那样结构判据会假绿）。

⇒ 建议索引里写成一对，并写明各自兜的是对方的哪个失效方向。单写行为判据，下一个人会把它当成充分条件；单写结构判据，过滤器的边界会没人注意。
