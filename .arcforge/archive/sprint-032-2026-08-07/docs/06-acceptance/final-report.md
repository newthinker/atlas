## 方法论：同一个形状的四次发作，四种身份

**共享工作区里的一次数据丢失，引发了四次独立的错误归因。没有一例是粗心——四例都是在各自信息最充分的位置上做出的最合理推断。**

**但四例分两组，处方完全不同——混在一起读者只会带走一半**（dev-agent-40 的分组）。

### 组一：有便宜的核实动作，没做

| 谁 | 把什么当成了事实 | 当时可用的核实 | 成本 |
|---|---|---|---|
| Skeptic lens | 「此刻 grep 不到」= 从来没有过 | `git log -S '<函数名>'` | 秒级 |
| qa-agent-9 | 「观察到 HEAD 变了」= 是它的子代理干的 | 自己的 shell 历史 / `git reflog` | 秒级 |
| leader | 「dev-40 写在交付物里的」= 已核实的事实 | 回一句「你怎么知道是 cp？」 | 一句话 |

**处方：那个便宜的检查，去做。**

### 组二：核实根本不可得，却没标「未知」

| 谁 | 把什么当成了事实 | 为何查不到 |
|---|---|---|
| dev-agent-40 | 「终态像我的 harness 会产生的样子」= 就是那种 harness | 看不到别的 agent 的进程/shell 历史，无从知道用的哪种还原 |

**处方完全不同：不是去查（查不到），而是在产物里写「机制未知」，把归因留给能查到直接证据的人。**

两组对应两种自问：
- 「我能不能查？」→ 能就去查，别推断。
- 「查不到怎么办？」→ **标注未知，而不是填一个最合理的猜测。**

**第二问才是最容易失守的**，原因是激励结构：

> **「未知」看起来像没干活，猜测看起来像结论**，而交付物的读者奖励后者。

⇒ 读者若只带走「多查一步」，就漏掉了「查不到时要敢写未知」——**后者没有任何工具能替你做**。

### Leader 那一例的止损动作（零成本）

它没有产生新判断，它**把一个标着推断的东西转成不标推断的、然后加权发出**。派发者的转述自带权重——同一句话从 Leader 嘴里出去，接收方复核的门槛更高。

修法不需要额外核实：**转述时把原始出处与原始置信标签一起带上。**

- 实际写的：「那个 harness 是你的 lens 子代理的」
- 应该写的：「**dev-40 在 discovery 里推断（未核实机制）是 cp 型 harness**」

同一条信息、同样一次转述、零额外成本，但接收方立刻知道该复核什么。**去掉的不是信息，是信息的来源和成色**——而成色决定对方要不要复核。

这是「我论证过 vs 我验证过」那条纪律在**转述场景**的版本：**不只自己产出时要标，转述别人的产出时要保留别人的标。** dev-40 转引 QA 的 125 时丢的也正是这个。

### 可复用判据（dev-agent-40）
> **当两种机制产生同一终态时，从终态反推机制的每一次都是猜测——哪怕猜对了也是。**

`cp $BAK $FILE` 与 `git checkout -- <path>` 终态不可区分（都是"文件回到较早版本 + git status 干净"）。正确写法是「发生了整体还原，**机制未知**」，把归因留给能查到直接证据的人。

**归因错了，处方没错**——两件事要分开记，否则下一个人会因归因被推翻而连处方一起丢掉。

## 写错的限度，比没写限度更难发现

TASK-006 的返工暴露了一个中间态。`identifiers_test.go` 的注释声称「任何新增的 SQL 语法都会被报成裸标识符」——被三个变异证伪。但 dev-agent-39 自查时发现，**它 discovery 里那句"正确的"限度也是错的**：

> 我原本写的是「只检查字符串字面量，**变量拼接**抓不到」——**而形态①根本不涉及变量拼接，它就是个字面量，照样逃。**
>
> 我知道有限度、也写了限度，**但把限度写错了**，而代码注释里那句更是把限度写没了。

⇒ 三个层级，严重性不单调：

| 形态 | 后果 | 发现难度 |
|---|---|---|
| 不写限度 | 读者自己会警惕 | 低 |
| 声称一个不存在的守护 | 读者不再自查 | 中（可被变异证伪） |
| **声称一个错误的边界** | **读者按错误边界自查，正好漏掉真实缺口** | **最高** |

最后一种最难发现的原因是激励性的：**一个写了限度的人，比一个没写的人更不会去复查那句限度**——他已经履行过这项义务了。

## 统一：让读者停止验证的两种文本（dev-agent-39）

「声称了不存在的守护」与「两份副本都自称原件」看起来是两回事，实为同形：

| 文本 | 读者信了什么 | 于是不做什么 |
|---|---|---|
| 过度声称的注释 | 「已被机制覆盖」 | 不再自查 |
| 无指针的复述 | 「这是当前事实」 | 不再去查权威源 |

**两者都不给纠错线索**：注释不说边界在哪，副本不说原件在哪，**于是读者没有理由怀疑**。

解法同形——**把「你不用再查了」换成「这是边界」或「这是去哪查」**：

- 注释列出三种实测逃逸形态 → 读者能自行判断某改动落不落在覆盖内
- 复述加一行权威源指针 → 读者知道出入时以谁为准

> **都是把「结论」降格为「结论 + 它的适用范围」。**

## 消息与状态的竞态（Leader 侧，本 Sprint 三次）

dev-agent-39 指出：**本 Sprint 有三条 Leader 消息基于已过期的状态**（我发出时任务已推进）。它按纪律直读核实后没有重复执行。

**危险的是重复执行不一定会被机制拦住**——`transition` 有迁移边校验会 DENY，但**重写 discovery / 重跑变异不是 transition，机制不拦**。

⇒ 两条：Leader 发指令前直读当前状态；收指令方执行前也直读一次。**后者是唯一在竞态窗口内仍有效的那道。**

**但这与角色无关，而且真正的理由不是「避免出错」。**

dev-agent-39 报告草稿状态后**主动自陈「我这条可能也是过期的」**，但它当时无从判断——读取与发送之间的窗口对它不可见。事后 Leader 澄清时序，证明那次**实际未命中**：它读取时草稿确实还是旧的，**报告在发出时是准确的**。

> **窗口是真的，命中是假的**——而它在事发当时无法区分这两种情况。

**这才是那句止损的真正理由。** 若只举「谁犯了错」的例子，读者会以为加限定是为了避免出错；实际上是为了在**无法自证**时仍然可用：

> **报告状态时加一句「以我读取时刻为准」**——把「是不是过期」这个报告者答不了的问题，变成读者能自己判断的信息。

零成本，且不要求报告者知道任何它不可能知道的事。这是「结论 + 它的适用范围」在**消息层面**的形态。

### 附带的第六例（Leader，同一形状的第二次）

两次的共同点：**转述的是别人的自我归咎**。自我归咎天然显得可信——**没人会怀疑一个人承认自己犯错时说的话**，于是它比其它推断更容易免检通过。

**而这只是接收方那一半。** dev-agent-39 补出了产出方那一半：

> 我写那句时，**压根没想到它需要证据**。我给别人的结论逐条标「我论证过 / 我验证过」，给自己的过错却直接用肯定句——因为承认错误在感觉上是**安全**的表述：它不抬高自己、不会误导别人往好处想，所以「谨慎」这个动作没有被触发。

**可操作的落点在产出方**，因为它不依赖别人：

> **「我错了」和「我判断错了什么」是两句话，后者需要证据。**

实例：那句该写成「**若**你在我发消息前已改好，那我这条就是同形的——**我无从核实**」。差别只在一个条件句，**但它把断言降回了推断**。

## 复现 ≠ 验证：判据问的是预测能力（test-agent-19）

TASK-006 的判据是「读注释的人能否预测那三个变异不会被抓住」。**注释把三种形态逐条列出了，所以复现它们是平凡成立的**——读者能背出这三个，不等于规则可用。

test-agent-19 因此分了三层，共 8 个变异：

| 层 | 做什么 | 结果 |
|---|---|---|
| 复现 | 三种形态 | 137/137 存活，对照组 `AND rowid > 0` KILLED 2 红 |
| **外推** | **注释里没列**的三个新情形检验规则 | **规则全部预测正确** |
| 正向对照 | 格式串**内部**加 `ORDER BY rowid` | KILLED ⇒ 注释不自相矛盾 |

外推层是关键：`+ " AND rowid IS NOT NULL"`（独立字面量但含已登记词）预测被抓 → 抓住；`+ " GROUP BY rowid"` 预测抓不住 → 未抓；运行时变量 `query += evilSuffix()` 预测抓不住 → 存活。**三个未列情形全中，说明规则可外推，而不只是三个样本被记住了。**

### N2 的坑：只看 FAIL 计数会得出相反结论

`GROUP BY rowid` 整体 **FAIL=16**，看起来"被抓住了"。**但红的全是行为测试**（`GROUP BY` 改变了查询语义），`TestSQLFragments…` 一条没红。

⇒ **判定必须落到"哪一条红了"，而非"红了几条"。** 这是「0 红三条自证」的对偶面：那条防的是假绿，这条防的是假红。

### 样本选择本身是取证质量的一部分

> `GROUP BY rowid` 同样是「独立字面量、无已登记关键字」，却**不是有效逃逸样本**——它改变语义、被 16 条行为测试杀掉。

要孤立证明「静态检查抓不住」，样本必须**同时**满足「静态检查不触发」**和**「行为测试也不触发」，否则变异被别的测试杀掉，缺口无法被孤立展示。**qa-agent-9 与 dev-agent-39 选的三个形态全部做到了 137/137、行为测试一条不动**——但两人都没写出这个选择标准。

**做到了而没说出来的东西，下一个人复制不了。** 这与「写错的限度」是同一枚硬币：一个是说了但说错，一个是做对了但没说。

   > **落盘保证正确，inbox 保证被看见。** 停机的 agent 不能轮询——`TeammateIdle` 是转 idle 前的一次性拦截，**不是心跳**。因此对已停机的 teammate，inbox 不是通知，**是唤醒的唯一手段**；派发/退回后不发 inbox，等于任务落盘了但没有人被叫醒。

   **开篇那条必须同时改，否则两条互相矛盾。** 「即使通知丢失，各角色通过轮询也能自愈推进」现在是错的，且是最危险的那种错：

   > **它让读者相信有一层兜底，于是不去建真正的兜底。**

   ——**又一次「声称了没有的守护」，这次声称的是自愈能力。** 准确版本要加前提：**对仍在运行的角色成立**，停机的不在此列。

   **「恰好去查」不是机制。** 目前 Leader 是这个缺口的唯一兜底，而那是「恰好」。若 Leader 在等判定、teammate 全部无待办，**全员静默且无错误信号——这个状态从外部看和「一切正常」完全一样**（又一次终态不可区分）。

   teammate 侧能做的只有「空闲前扫干净」，**但那只保证不带着活停机，不保证停机后能被叫醒**——后者只有派发方给得了。

## 取证质量：本轮的四条实证

**① 「靶不存在即失败」接住了一次比假绿更隐蔽的假绿。** test-agent-18 构造 MQ3 时把 `classify.go` 的 import 靶写成 `import (`，实际是 `import "fmt"` 单行 ⇒ harness 报「靶不存在(0 次)——变异失败」并拒绝替换。

> 若 harness 静默跳过，我会拿到一个「**根本没施加变异**」的全绿，并极可能读成「MQ3 存活」。

**这比编译失败伪造的假绿更隐蔽——连编译都是好的。** 三条自证里的「变异 diff 非空」正是防这一种。

**② 可证明的等价变异不必停在三条自证。** MX4（`Classify` 的 `>` 改 `>=`）存活，但可**证明**等价：第一个 case 已捕获全部 `==`，求值到第二个 case 时 `incoming != LatestRevision` 恒成立，故 `>=` ≡ `>`。**证明比三条自证强**——后者只说明"这次没测出来"，前者说明"永远测不出来，且不该测"。

**③ 两个维度合起来才构成守护，任何一条单独都不够。** `%q` 形态的注入变异需要**双引号载荷**与**逐列遍历**两条修复同时到位才打得中：只有双引号载荷但固定首列、或只有逐列但全是单引号载荷，都杀不掉它。**「正交」是实测出来的，不是设计时声称的。**

**④ 选错取值 = 写了等于没写，且全绿无信号。** 同一个 MQ3，取值保持 RFC3339 → KILLED(134)；取值弱化为 date-only → **存活，PASS=137，无一转红**。原因是时间序实现会退回字典序兜底。
