## 6. 方法论产出

**AD-27** 从一个覆盖率读数问题长成本 sprint 的测试方法论主干（27 条 AD / 775 行）：

1. **覆盖率读数非确定** —— sankey 实测 12 次：10×97.5% / 2×97.8%；比较须多次采样
2. **变异记录写「N 次中红了几次」**，且是**用例层面**；循环是把 p 提到 1 的手段
3. **`N = ceil(ln(target)/ln(1−p))`，p 必须实测**——直觉的 50% 被 20 万次采样推翻为 7/8；
   且**样本量本身也要够**（n=25 测得的 0.24 被 600 次样本修正为 0.115）
4. **结构性保证 > 概率性压制**——两者产出同样的绿色，强度差一个量级。
   先问「能不能让它必然发生」，问不出来再问「跑多少次才够」
5. **变异坑六类**（本 sprint 全部实际发生）：
   还原失败致累积 / 编译失败当成存活 / `sed` 未命中 / 语义等价（**无机械堵法，禁止默认归类**）/
   **执行环境本身错误**（对照组必须与变异组同环境且实测 0 红）/
   **fixture 与生产不同**（**变异测试对此形态无效**，问题在 fixture 里不存在的那一行）
6. **「端到端用例」可能是两条独立的链**——实测页面环红而 API 环全绿；必须两环都断言
7. **p 不是代码的属性，是 fixture 的属性**——「满分的 N/M」要问是在哪个档位测的

**贯穿全程的判据**：**通过的断言 ≠ 有判别力的断言**。本 sprint 出现的实例包括
恒真断言（fixture 值与断言值相同）、空洞用例（无变异覆盖）、绿但盲（fixture 缺项）、
文本级伪守护（C7/C7b）。

>
> 人类于 2026-07-26 修改了 `.claude/hooks/task-completed.sh`（加入任务级 `coverage_floor`），
