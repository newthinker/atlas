## 1. (a) 结构性论证 —— 我独立审计，**成立**

### 1.1 论证依赖的源码事实（我逐一实读，非引用 dev 说法）
- `buildQuarters`（`periods.go:96-110`）：`byPeriod[label]` 是 `segmentBuckets`
  = **`map[period_end]map[segment_key]float64`**，即桶**以 period_end 为键**。
- `segmentsAt`（`periods.go:134-141`）：
  `for bucketEnd, segments := range buckets { if sameQuarter(bucketEnd, end) { return segments } }`
  —— **命中即返回**，这正是概率性的来源。
- `sameQuarter(a,b)`（`periods.go:200-213`）：`a == b → true`；
  `time.Parse(a)` 失败 → `return false`（**M1**）；`time.Parse(b)` 失败 → `return false`（**M2**）。
  调用点 `a = bucketEnd`、`b = 本期 period_end`。

### 1.2 论证核验
新 fixture：`funds` 1 行（`2026Q3` / `2026-03-31`），`segs` 1 行（`2026Q3` / **`"n/a"`** / cloud / 26b）。
⇒ `byPeriod["2026Q3"] == {"n/a": {...}}`，**恰一个键**。

| 充要条件 | 是否必然成立 | 依据 |
|---|---|---|
| (1) 循环体以某 `bucketEnd` 执行 | **必然** | 一元 map 的 for-range 必然且仅有一次访问该唯一键；「命中即返回」在**只有一个候选**时无从短路 —— 与遍历顺序无关 |
| (2) `bucketEnd != end` | **必然** | `"n/a" != "2026-03-31"`，fixture 静态性质 |
| (3) `bucketEnd` 不可 `time.Parse` | **必然** | `"n/a"` 非 `DateOnly` 日期，fixture 静态性质 |

⇒ M1 分支**必然执行**，**p = 1**（不是「p 很高」）。**(a) 论证独立认可，无需借助任何跑动次数。**

### 1.3 dev 的 (1) 论证措辞我认可
「命中即返回在只有一个候选时无从短路」是本论证的关键一步，它把 `segmentsAt` 的短路语义
从「威胁」化解为「无关」，而不是去论证「短路不会发生」。这是正确的论证形状。

### 2.1 我另找到一处自检**盲区**（不构成缺陷，说明如下）
