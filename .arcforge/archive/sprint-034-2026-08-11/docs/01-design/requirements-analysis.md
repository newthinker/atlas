## 需求文档自带的两处 spec 修正（均已并入任务）

**修正 1 · 句式模板是 7 类不是 5 类。** spec §3 D2 漏了利率与外汇——它们**既无方向词也无标准单位**，是独立句式：

```
同业拆借加权平均利率为1.36%              ← 无方向词，且后跟「低0.06个和0.21个百分点」干扰
国家外汇储备余额为3.36万亿美元            ← 单位是「万亿美元」
人民币汇率为1美元兑7.0288元人民币         ← 数字夹在「兑」与「元人民币」之间
```

**修正 2 · 「本外币」干扰（spec 的 F4 未覆盖）—— 这是本 Sprint 最高风险点。** 两份样本都存在，且**本外币在前**：

```
月末，本外币存款余额336.14万亿元…。月末人民币存款余额328.64万亿元…
```

正则若写 `存款余额([0-9.]+)万亿元`，**先匹配到 336.14**——**量级相近、格式正确，任何闸门都拦不住**。锚点必须含「人民币」且排除「本外币」。

## 风险点

**R1（最高）—— 静默取错值。** 修正 2 那一类：抽到的是同一字段的另一个口径，**数值合法、量级正确、格式无误**，下游任何校验都发现不了。DoD 必须为「本外币」形态设专门判据，且**不能只测「能抽出值」**。

**R2 —— 作用域切错导致重复赋值。** 全局约束写明「同一字段被赋值两次即报错」，理由是**静默取最后一个最坏**。这条要成为可验证的 DoD，而非仅实现里的一个 if。

**R3 —— 默认值掩盖失败。** 三条全局约束都在防同一件事：符号从方向词读（不从数字推）、单位后缀捕获不到即报错（不默认某单位）、版本形态不认识即报错（不降级）。**共同形状是「拿不准时不要猜」**。

**R4 —— golden 表的可信度。** 约束要求「手工抄自原文，不得由解析器生成」。若由解析器生成，端到端测试会退化成恒真（拿实现的输出去校验实现）。**这条无法用测试守住，只能靠 DoD 明写 + 验证者抽查原文。**
