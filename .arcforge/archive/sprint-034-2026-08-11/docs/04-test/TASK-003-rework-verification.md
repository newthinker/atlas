## 二、CRITICAL 的核心：我用**同碰撞不同成因**证明修法覆盖根因

### 2.1 先修正我自己的一个过头结论

我最初构造了三种「别的成因」（半角空格 / 全角空格 / 整节截断），四种全被拦下，据此写了
「修法覆盖根因」。**那个推理是错的**——复查发现这三种在**修复前也会被拦下**：它们产生
**7 个板块**，而 7 不是任何已知版式，版式分支本就会报错。

**它们不证明修复的必要性，只证明修复的一致性。** 真正危险的只有一种输入：
**恰好丢掉两个社融节** ⇒ `(6 板块, 无社融)` ⇒ 与一份**合法 v1 逐位相同**。

### 2.2 决定性实验：四种不同成因，同一个碰撞

| 成因（都插在 `<strong>一、` 与 `<strong>二、` 前） | **修复前** | **修复后** |
|---|---|---|
| `&nbsp;`（QA 的反例） | 6 段 → `rule@v1` / `err=nil` / **27 Values** | 报错 / **0 Values** |
| 半角空格 | 6 段 → `rule@v1` / `err=nil` / **27 Values** | 报错 / **0 Values** |
| 全角空格 | 6 段 → `rule@v1` / `err=nil` / **27 Values** | 报错 / **0 Values** |
| 制表符 | 6 段 → `rule@v1` / `err=nil` / **27 Values** | 报错 / **0 Values** |
| `<em></em>` 空内联标签（**阴性对照**） | 8 段 / 正常 / 54 Values | 8 段 / 正常 / 54 Values |

⇒ **四种机制各异的成因，在修复前全部产生同一个静默误判**（一份 v2 年报被判成 v1，
27 个字段正确入库、另 27 个被下游读作「本期模板本就没有」）；**修复后全部拦下**。
阴性对照证明守卫不是对任何插入都报错。

**这才是 `fix_items[2]`「说明修法为何覆盖根因而非只覆盖那个反例」的证据。**
dev-43 的 discovery 里列了 7 种机制，与我独立做的这组一致。

### 2.3 修法本身的论证我认同

它选择**校验序号（报告自带的冗余）**而不是去堵前导空白，理由写在
`checkSectionOrdinals` 的注释里：

> 全角空格、实体、标签嵌套变化、抓取截断，任何让某个标题行匹配不上的原因，后果都是同一个。
> 序号是报告自带的冗余，校验它等于让「丢了一节」这件事本身可检测，**与丢失的原因无关**；
> 而逐个去堵成因，永远只能堵住已经见过的那些。

**这个取向是对的**，2.2 的实验正是它的实证。

### 2.4 两个我特意核过的细节

- **校验位置先于版式判定**（`detectExtractor` 开头）。注释说明了为何不能放在后面：
  「残缺的 v2 在版式上与合法的 v1 无法区分，等到版式分支才判就已经晚了」。**顺序正确。**
- **期望前缀带「、」**：`want := sectionOrdinals[i] + "、"`。少了顿号，「十」会前缀匹配
  「十一」，于是「一…九、十一」（第十节丢了）被判成连续——**正是本次要堵的同一类缺节**。
  dev-43 记录该变异（N3）首轮存活并已补测杀死。
