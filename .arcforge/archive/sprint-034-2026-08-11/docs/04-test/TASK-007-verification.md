### 4.1 相对误差 `8.12e-17` —— **撤回，它是对的**

我最初测得 `1.5127e-16`，与它报的 `8.12e-17` 差约 1.86 倍。用高精度十进制追到底：

```
float64(4.81) 精确值   = 4.80999999999999960920149533194489777088165283203125
十进制 4.81            = 4.81
输入侧绝对差            = 3.9079850466805510e-16
输入侧相对差 |d|/4.81   = 8.125e-17      ← dev-43 报的数
输出侧 f*10000 精确值   = 48099.9999999999927240423858165740966796875
输出侧绝对差 vs 48100   = 7.2759576141834259e-12   （恰为 1 ULP）
输出侧相对差            = 1.513e-16      ← 我测的数
```

**两个都对，测的是不同的量**：它测**输入侧**（源字面量 `4.81` 的表示误差，即误差的起点），
我测**输出侧**（×10000 之后相对 48100 的误差）。

⇒ **不是错误**。唯一可改进处：discovery 未写明测的是哪一侧，读者容易与输出侧混淆。
**建议（非阻塞）**：措辞补一句「输入侧：`4.81` 本身的表示相对误差」。

### 4.2 `store_test.go` 的 `+17/-2` —— **措辞失误，实质结论不受影响**

权威值是 **`+15/-2`**。来源已查明：

```
git diff --stat    … -- store_test.go  →  17 +++++++++++++--
                                          1 file changed, 15 insertions(+), 2 deletions(-)
git diff --numstat … -- store_test.go  →  15   2
```

`--stat` 里的 **`17` 是「总变更行数」（15 插入 + 2 删除）**，不是插入数。
写成 `+17/-2` 等于把 2 行删除计了两次。

⇒ 该条出现在 **`[佐证]`** 行，用于支撑「并非纯新增文件，`store_test.go` 有必要修改」——
**这个实质结论完全成立**（它确实是既有文件被修改，且这正是 T6 追加 `Parse` 到导出面名单所致）。
**建议（非阻塞）**：报差异行数一律用 `--numstat`，`--stat` 的首数字是总变更行。
