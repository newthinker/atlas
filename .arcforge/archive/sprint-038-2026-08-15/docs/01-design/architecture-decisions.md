# M1c-1 架构决策记录

## ADR-M1c1-01 · index 为主 + 搜索交叉校验，抓取集取并集

**状态**：已定（人类 2026-08-14 裁决）

**背景**：用户提出「可以通过关键词搜索缩小查询范围」。实测站内搜索（`wzdig.pbc.gov.cn`）确实
可用且更精确：`searchArea=title` + `qAll`（AND 语义）把 1324 条收窄到 24 条，全区间三个关键词
共 **82 页**，对比 index 翻页的约 150 页。搜索结果还直接给出 manifest 需要的三样（绝对 URL、
标题、发布日期），不必解析列表项结构，也不依赖 `parsePaging`。

**但实测同时暴露一处不自洽**：2020 全年搜「社会融资规模存量统计数据报告」= 24 条 = 12 期 × 2
栏目、完美齐全；而全区间同一关键词 = 137 条，理论值 79 个月 × 2 栏目 = 158 条，**差 21 条**。
2020 年是全的，缺的在别的年份，成因未查。

**决策**：index 翻页做主路径（保住 spec 全部既有守卫：0 条报错 / 按日期停 / MaxPages 兜底），
搜索做**独立第二来源**，抓取集 = A ∪ B，两个差集写进 manifest 与 final-report。

**理由**（三个方案的分野）：

| 方案 | 那 21 条差额会变成什么 |
|---|---|
| 只用搜索 | **静默漏** —— 无第二来源可比，manifest 少了几十期而没有任何错误 |
| 只用 index（照 spec 原样） | **根本不会被发现** —— 本次实测才第一次看到它 |
| **两者并跑（选定）** | **可观测的不一致** —— 差集落 manifest，且它正好是 spec §10 第 3 问「哪些期缺篇」的答案 |

搜索漏了搜索自己不会说。这正是 spec §4.2 立那条「0 条 ⇒ 报错」守卫时最担心的失效模式，只是
载体从「分页控件解析失效」换成了「检索索引不全」。

**代价**：请求量最大（约 482 次 ≈ 9 分钟，vs 单路 400 / 322）；多约 60 行搜索侧代码。
`B \ A` 非空判**告警不判失败**——它意味着 index 漏了，但并集已收进抓取集，交付物不缺。

**推翻本决策需要的证据**：证明那 21 条差额是「部分期次确实只在一个栏目发」而非索引不全。
那需要对着 index 侧逐期核对——**恰好就是本决策要做的交叉校验**。

## ADR-M1c1-02 · 搜索侧失效不阻断主路径（fail-open）

**状态**：已定

**背景**：搜索侧依赖两个脆弱点——第三方检索服务 `wzdig.pbc.gov.cn` 的可用性，以及
**`advtime=5`（自定义时间范围）这个前端已注释掉、后端仍接受的未公开参数**。未公开行为比公开
参数更容易在无预告的情况下变。

**决策**：搜索侧任何失效（HTTP 非 200、返回条数骤增到全站量级、解析不到总页数）⇒ **打 WARN、
跳过交叉校验、在 final-report 注明**，主路径（index 抓取）照常完成并正常退出。

**理由**：与「矩阵缺失 fail-closed」刻意相反。矩阵是授权依据，缺了无从判权必须拒；而交叉校验
是**附加防线**，让它有权否决主路径交付，等于把一个不可控的第三方服务放到交付路径的关键链上。

**⚠️ 有声跳过，不静默**：跳过必须打 WARN 并写进 manifest（`search_skipped_reason`）与
final-report。否则「这次没做校验」与「校验通过」在读者看来完全一样——那就是本 ADR 要防的
失效模式本身。

## ADR-M1c1-03 · 测试样本改用 p146，7 位 id 复用既有 p18

**状态**：已定（人类 2026-08-14 裁决）

**背景**：spec §9 指定「第 145 页（2020-03）三种标题齐全」。实测 p145 的 15 条列表项里只有
**2 篇**报告（社融存量 2020年3月、社融增量 2020年一季度），**没有《金融统计数据报告》**。
`functional[0]`（三种标题都识别）无法在该页验证。

**决策**：样本改用 **p146**（`2020年2月` × 金融统计 / 社融存量 / 社融增量，三种齐全，
38201 字节）。7 位 article_id 的 `functional[1]` **复用仓库既有** `testdata/pboc-index-p18.html`
（其中报告 id 是 `5868082`）。

**理由**：进 git 的新增历史页样本仍只 1 份，与 Global Constraints「只有那份 38KB 历史页测试
样本进 git」一致。p145 的额外价值（含「一季度」形态的增量报告，即 spec §7 那个坑）对本迭代
无用——本迭代不做期次映射；而它会出现在真跑产出的 runtime 快照里，M1c-2 要用时不缺。

**附带发现**：p147 一篇报告都没有 ⇒ 它是「有列表项但其中 0 条是报告」的**真实**样本，
正好给 design-spec §3.2 那条「这个形态不报错」的用例做语料，不必合成。

## ADR-M1c1-04 · 产物落仓库外绝对路径

**状态**：已定（人类 2026-08-14 裁决）

**背景**：spec §3 写 `--out data/backfill`（仓库内相对路径）。但 dev 在自己的 `git worktree`
里干活，`git worktree remove` 会连产物一起删掉；15MB 落在仓库内还需要 `.gitignore` 兜住误提交。

**决策**：`--out ~/hestia-backfill-2026-08-14`（仓库外绝对路径）。`--out` **无默认值、必填**。

**理由**：三个问题一次消掉——worktree 拆掉产物仍在；不在仓库内所以不可能误提交；会话外备份
直接 `cp -r`。`--out` 不设默认值是为了让「误落进仓库」需要显式打出来才会发生。

## ADR-M1c1-05 · 不复用 Discover，不新建子包

**状态**：沿用上游 spec §8 与 ADR-0009，本次实测未发现推翻理由

`Discover` 的语义是「找**未入库的新**报告，碰到已知的就停」；回填要的是「翻到 2020-01 为止，
把**所有**匹配的都要」。判停条件相反，标题正则也只认一种。

复用的是更下层的部件：`parsePaging` / `pageURL` / `resolveURL` / `Fetcher` / `tagRE` ——
它们是纯粹的页面机制，与「找什么」无关。这几个都是包内**未导出**的，子包用不了 ⇒
`backfill` 放在 `internal/hestia` 包内，文件名加 `backfill_` 前缀。

**本次实测的一条补强**：省市分行报告（「2020年11月厦门市金融统计数据报告」等 30+ 家）被既有
`reportTitleRE` 的「期次段紧跟报告种类」机制天然挡住。新的 `backfillTitleRE` 必须保留这个
「紧跟」结构——放宽成「标题里含『金融统计数据报告』」会把它们全收进来。
