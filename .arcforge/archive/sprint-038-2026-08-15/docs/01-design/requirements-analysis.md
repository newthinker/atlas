### 3.3 实测发现的新事实（spec 与现有代码均未记录）

**a) 同一篇报告在两个栏目各有一份**

```
/goutongjiaoliu/113456/113469/5837468/index.html                           ← 沟通交流（现有 Discover 翻的）
/diaochatongjisi/116219/116225/35ec0aa27604417888826e7ff128cc4a/index.html ← 调查统计司
```

调统司那份**不出现在 index 页**，只出现在搜索结果里 ⇒ 搜索侧必须按 URL 前缀
`/goutongjiaoliu/113456/113469/` 筛，与现有代码口径统一。

🔴 **本节原先写「后者 article_id 是 32 位 hex」——那是错的，且错因值得记**（dev-agent-57 在 TASK-004
实测纠正）：6 条 `/diaochatongjisi/` 里只有 **2 条**是 32 位 hex，另 **4 条是 19 位纯数字**
（`2025080618505078072`），**与 goutongjiaoliu 侧完全撞形**。

我当时只看了搜索结果第 1 页的**前 4 条**，前两对恰好都是 hex，就概括成了 id 形态规律。
**这是「用样本形状当契约」** —— `discover.go` 把这种错称为「本包最贵的一次」（`\d{14,}`），
而我是在一个专门为防它而立的项目里又犯了一遍。

⇒ **筛选判据只能是栏目前缀，永远不能是 id 形态。**

🔬 **成因是结构性的，不是「我不够谨慎」**（dev-agent-57 在交付中指出，比「个人失误」这个定性有用得多）：

央行两个栏目的 article_id 形态**按站点重建时间分层**（2026-06-26 重建前是 19 位时间戳，重建后是短数字/hex），
而搜索结果**按发布时间倒序** ⇒ **第 1 页前几条必然全是重建后的新形态**。

⇒ 「翻第 1 页看几眼」这个动作，在这个语料上**系统性地**采不到旧形态。它会打到任何这么做的人身上——
dev-agent-57 自己也说，它撞见那 4 条 19 位纯数字，是因为要写 `functional[2]` 的断言、**必须逐条列出全部 12 条**，
不是因为它更谨慎。

⇒ **判据不是「这个样本是真的吗」，而是「这个样本占生产语料的几分之几」。**
前者恒为真（我看到的那 4 条确实都是 hex），后者才能暴露分层。


**b) 省市分行报告被现有正则天然挡住**

搜索命中大量「2020年11月**厦门市**金融统计数据报告」「2020年11月份**吉林省**…」。现有 `reportTitleRE` 要求期次段**紧跟**「金融统计数据」，省市名插在中间 ⇒ 全部被拒。这印证 `discover.go` 注释里「挡住干扰项的自始至终是『紧跟』」，无需额外处理。

**c) 站内搜索接口可用，但自身有一处不自洽**

接口与参数见第 4 节。关键数字：

- 2020 全年 `qAll=社会融资规模存量统计数据报告` = **24 条** = 12 期 × 2 栏目，**完美齐全**
- 全区间（2020-01-01..2026-08-14）同一关键词 = **137 条**；而 2020-01..2026-07 是 79 个月 × 2 栏目 = **158 条**

差 **21 条**。2020 年是全的，缺的在别的年份，**成因未查**。

⚠️ **这是本次分析最重要的一条**：它说明搜索会漏，而**搜索漏了搜索自己不会说**——正撞在 spec §4.2 最担心的失效模式上（「回填看起来跑完了、manifest 里少了几十期，而没有任何错误」）。该差额**无法在搜索内部判定**，只能靠独立第二来源。

## 4. 站内搜索接口（实测参数）

```
GET https://wzdig.pbc.gov.cn/search/pcRender
  pageId=c177a85bd02b4114bebebd210809f691
  advSearch=true
  searchArea=title                 # 只搜标题（另有 '' 默认 / text 正文）
  qAll=<关键词>                     # AND 语义
  sr=dateTime desc                 # 按发布时间倒序（'date desc' 返回 302）
  pNo=<页码>                        # 每页固定 12 条
  advtime=5&startTime=2020-01-01&endTime=2026-08-14
```

**`q` 与 `qAll` 差 25 倍**（同一关键词、同为 `searchArea=title`）：

| 参数 | 条数 | 页数 |
|---|---|---|
| `q=社会融资规模存量统计数据报告`（默认 area） | 1324 | 111 |
| `q=…`（area=title） | 610 | 51 |
| `qAll=…`（area=title + 2020 全年） | **24** | 2 |
| `advepq=` / `adveq=` 单用 | 549141 | 45762 |

`advepq`/`adveq` 单用等于空查询（返回全站），**别用**。加引号做短语无效。

🔴 **上表的每一行都是实测，但从它得出的「q 比 qAll 多 25 倍」是错的**（2026-08-14 由 test-agent-28
在 TASK-004 验证中指出，Leader 已逐条复现）。**行与行之间不是单变量对照** —— `1324` 那行同时改了
三样：`searchArea`（默认含正文 vs title）、`q` vs `qAll`、有无日期窗口。

**严格单变量对照的真实倍数是 2.0–2.5×**：

| 固定条件 | `qAll` | `q` | 倍数 |
|---|---|---|---|
| `searchArea=title` + 日期窗口 | 137 | 276 | 2.01× |
| `searchArea=title`，无日期 | 240 | 610 | 2.54× |

`1324` 的真实含义是「**默认 area（含正文）+ q + 无日期**」，它与 `searchArea=title` 的 610 构成的
才是单变量对照（**搜正文 vs 只搜标题 = 2.17×**）。

⇒ 结论不变（`qAll` 严格窄于 `q`，仍应使用 `qAll`），但**别再引用「25 倍」这个数**。
⚠️ 方法学教训：**把多个变量一起改，然后拿首尾两行相除** —— 得出的倍数不属于任何一个变量。


⚠️ **`advtime=5`（自定义时间）在前端 radio 里已被注释掉，后端仍接受**。这是**未公开行为**，比公开参数脆弱，必须有降级路径（见 design-spec 的 ADR-M1c1-02）。

🔴 **「`advtime` 失效时返回全站量级（549141）」是错的**（2026-08-14 由 test-agent-28 实测推翻，
Leader 已逐条复现，四个数字逐字相符）：

| 场景 | 实测 `total-records` |
|---|---|
| 现状 `advtime=5` + 日期范围 | 137 |
| **`advtime` 参数被丢弃** | **240** |
| **`advtime=0`** | **240** |
| `金融统计数据报告` + 无日期过滤 | **1136**（三关键词最大值） |

**`advtime` 失效返回的是「该关键词的全部历史结果」（240 / 1136），不是全站量级。**
`549141` 是**无关键词空查询**的值 —— 那是**另一种**失效模式，且实测那种模式连 `total-records`
字段都取不到，会被「计数字段缺失 ⇒ 报错」拦下。

**后果**：据 549141 设的 5000 上界，距真实失效量级（最大 1136）差 4.4 倍
⇒ **该守卫永远不会因 advtime 失效而触发**，而它的错误文案恰恰指认 advtime。
已转 TASK-004 `review_fix`（FIX-1）：改用**「解析出的每条 `Published` 必须落在 `[from, to]` 内」**
—— 检测**结果的性质**而非**数量**，与语料规模无关。

⚠️ 通用形式：**用「数量异常」当守卫，需要先知道异常时的数量是多少**；而那个数往往没人实测过，
于是阈值订在一个永远够不到的地方。**直接检测「约束有没有被满足」比检测「结果像不像话」可靠。**


**全区间请求量**：

| `qAll` 关键词 | 条数 | 页数 |
|---|---|---|
| 金融统计数据报告 | 692 | 58 |
| 社会融资规模存量统计数据报告 | 137 | 12 |
| 社会融资规模增量统计数据报告 | 137 | 12 |
| **合计翻页请求** | | **82** |

## 6. 三处人类裁决（2026-08-14）

| # | 决策 | 理由 |
|---|---|---|
| 1 | 测试样本用 **p146 + 复用既有 p18** | p146 三种标题齐全（p145 不满足）；p18 已在 git 且含 7 位 id ⇒ 新增样本仅 1 份 |
| 2 | **index 为主 + 搜索交叉校验**，抓取集 = A ∪ B，差集写进 manifest 与 final-report | 保住 spec 全部既有守卫；把已观测到的 21 条差额从「静默漏」变成「可观测的不一致」；差集正好是 spec §10 第 3 问「哪些期缺篇」的答案 |
| 3 | **完整真跑**，`--out` 指向**仓库外绝对路径** `~/hestia-backfill-2026-08-14/` | worktree 拆掉产物仍在；不可能误提交 15MB；会话外备份直接 `cp -r` |

## 7. 复杂度与风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 搜索索引不全（已观测 21 条差额） | manifest 缺期，M1c-3 入库缺字段 | 决策 2 的交叉校验：差集可观测且落 manifest |
| `advtime=5` 是未公开参数，随时可能失效 | 搜索侧时间过滤失效 | 搜索侧是**校验路径不是主路径**；失效时按 `sr=dateTime desc` 客户端判停降级，且校验缺失不阻断主路径交付（打 WARN） |
| 第三方检索服务 `wzdig` 不可用 | 交叉校验做不了 | 同上：主路径（index）不依赖它 |
| 400+ 请求跑 9 分钟中途断 | 前面白抓 | manifest 逐篇追加落盘 + 断点续抓（`functional[4]`/`[5]`、`non_functional[1]`） |
| 站点在回填期间再次改版 | 解析失效 | 「某页 0 条 ⇒ 报错」（`boundary[0]`）；index 与搜索两侧同守此则 |
