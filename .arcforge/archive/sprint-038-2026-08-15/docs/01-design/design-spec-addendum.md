## A. 三处必须先定义的语义（不定义则 DoD 无法判真假）

### A1 · `--from` 的语义 = **发布日期**，不是期次

**歧义来源**（reviewer 实测）：spec §4.3 的代码 `oldestOnPage.Before(from)` 比较的是**发布日期**，
而 §10 的「80 期（2020-01 至今）」数的是**期次**。两者差约一个月——实测 **2019 年度的三篇发布于
2020-01-16**，按发布日期会被 `--from 2020-01` 收进来，按期次则不属于「2020-01 至今」。

**定义**：`--from` **一律按发布日期**（与既有代码一致，且翻页判停本来就只能看发布日期——
index 按发布时间倒序，期次在页面上根本不成序）。

**推论**：`--from 2020-01` 的产出**包含 2019 年度的三篇**（发布于 2020-01-16）。这是刻意的，
不是缺陷——它们同属要回填的历史。M1c-2 若只要 2020-01 起的期次，自己按 `title` 过滤。

⚠️ 这条必须写进 `--from` 的 flag 帮助文本，否则下游会按期次理解它。

### A2 · sha256 的作用域 = **首次抓取时计算**，本迭代不做重抓比对

**矛盾来源**（reviewer 指出）：§6 称 sha256 是「重抓时检测内容是否变了…**唯一能发现改版的途径**」，
而 §5.2 / `functional[5]` 规定「已在 manifest 且文件存在的直接跳过，**不重发请求**」——
跳过就不会重抓、不会重算，**该机制被同一份文档的另一条设计关掉了**。

**定义**：sha256 **只在首次抓取该篇时计算并写入 manifest**。它在本迭代的用途是
**让下游能验证本地文件未被篡改/截断**，**不是**「发现站点改版」。

「发现站点改版」需要显式的重新抓取模式（如 `--recheck` 强制重抓并比对 sha256）——
**本迭代不做**，登记为 M1c-2 的可选项。⚠️ 别在 §6 的措辞上留「唯一途径」这句话误导下游。

### A3 · index 快照的文件名不以页码为唯一键

**矛盾来源**（reviewer 指出）：§4.3 自己论证「页码随新文章上架而漂移，今天的第 150 页明天就不是」，
§3 却把快照定名为 `index/11040-<N>.html`。⇒ 重跑时同一个文件名会对应**不同内容的页**，
而 §5.3 存 index 页的目的正是「重跑与 M1c-2 的核对都能离线做」，键不稳定时会对错页。

**定义**：index 快照落名 `index/<抓取序号>-<该页最新条目日期>-<该页最老条目日期>.html`
（如 `index/007-2020-04-10_2020-03-25.html`）。页码作为 manifest 里的元数据保留，不作文件名唯一键。

## C. 一个会毁掉交付对账表的方法学陷阱（reviewer 自己踩过）

macOS 的 `sort`（2.3-Apple(199)）在 `en_US.UTF-8` 下**把任意两个汉字判为相等**：

```
$ printf '存\n增\n' | sort -u           → 1 行   ← 被判相等
$ printf '存\n增\n' | LC_ALL=C sort -u  → 2 行
$ printf '存\n增\n' | uniq              → 1 行   ← uniq 同样折叠
```

对 748 条语料：默认 locale 的 `sort -u` 数出 **21** 个唯一标题，`LC_ALL=C` 与 python 都是 **28**
——**静默少 25%，而少掉的恰好是「存量」/「增量」这一对**，也就是本迭代赖以区分三种报告的那个字。

⚠️ **一个用来防静默漏的对账机制，会被同一类静默漏毁掉。**
⇒ 凡产出交付证据的统计，一律 `jq` / `python3` / `LC_ALL=C`，**禁止**裸 `sort -u` / `uniq`。
（与 CLAUDE.md 已登记的 `grep -o -E` 多字节交替坑同族。）

## D. 完整性对账（新增 TASK-008 的立项理由）

reviewer 的核心结论，Leader 核验后采纳：

> 现有 DoD **全是否定式或局部判据**——「某页 0 条则报错」「翻满则报错」「单篇失败记 failed」，
> 每条守住一种**已知**成因。而「manifest 完备」是一个**全局、正向**的性质，
> 没有任何一条断言「应该有 N 篇，实际有 N 篇」。

四条设计叠起来正好构成一条完整的静默漏通道：

1. 「0 条报错」只在**整页归零**时触发——部分漏（少认一种期次表述 / 边界页被 break 跳过 / 页码漂移）**永远不触发它**
2. 「`--from` 太新 ⇒ 不报错」主动开了一条**静默零通道**：`--from` 打错一位 ⇒ 0 篇 + 退出码 0
3. 「已在 manifest 就跳过」让**漏一次就固化**，第二次跑也不会补
4. §10 三个问题是**回顾式**（「抓到多少」）而非**期望式**（「应抓到多少」）——抓到 180 篇就报 180 篇，没有任何东西说它该是 214

## E. 留给 M1c-2 的坑：比 spec §7 记的宽一倍

spec §7 只举了「存量说 3月、增量说 一季度」。实测**四种形态**：

| 期次 | 金融统计 | 社融存量 | 社融增量 |
|---|---|---|---|
| 2020-03 | 一季度 | **3月** | 一季度 |
| 2020-06 | 上半年 | **6月** | 上半年 |
| 2019-09 | 前三季度 | **9月** | 前三季度 |
| 2019 年度 | (无期次段) | **(无期次段)** | (无期次段) |

即：累计期次里**只有存量退化成月**，而**年度期次三者都无段**（存量不写「12月」）。
spec §7 只写了第一行 ⇒ M1c-2 若照它写映射表会漏后两行。
**§7 自称「留给 M1c-2 的坑，现在只记录」，记漏了等于没记。**

## G. 🔴🔴 本节曾记录一个「反例」，**那是假的，已撤回**（Leader 自纠，2026-08-14）

**先说结论：`boundary[3]` 的判据 `delta < 0 ⇒ 报错` 保持不变，dev 的实现没有问题。**
本节保留下来不是为了那个结论，是为了记录**Leader 是怎么造出一个假实测的**。

### 我曾在这里写过什么

Leader 声称实测出 `p147.oldest = 2020-02-20 < p148.newest = 2020-02-21`（delta = −1），
据此判定「按 `>=` 硬报错会在真实数据上误报 4.5%」，并要求 dev 降级成告警。

### 它为什么是假的

dev-agent-55 复现不出来（自抓 22 对：严格大于 11 / 取等号 11 / **反例 0**，`delta ∈ [0,5]`），
并先指出了 **Leader 叙述内部的矛盾**：

> 你写「p147 末尾有 3 条 `02-21`」，那 `p147.oldest` 就该是 `02-21`，**不可能是 02-20**。

Leader 随后查了自己那批 HTML 的**文件时间戳**，这是决定性证据：

```
p145..p152 的抓取时刻横跨  15:44:19 / 17:42:2x / 18:00:07   —— 跨度 2 小时 16 分
```

而当前磁盘上的 p147 末三条是 `['2020-02-22','2020-02-21','2020-02-21']`（oldest = **02-21**），
与 dev 实测一致、与当时报告的 02-20 不同。

⇒ **Leader 拿不同时刻抓的两页做了相邻页比较。** 期间站点有新文上架、分页边界移了一格，
于是造出「后一页比前一页新」的假象。元凶是脚本里那句 `[ -f "p$p.html" ] || curl ...`：
它跳过已存在的文件，让新抓的页与几小时前的旧页混在一起，而这件事**不会有任何输出提示你**。

### 违反的是本项目已登记的纪律

> **背对背**：任何「A vs B」的比较必须**同一时刻并排**产生。跨时间点采样得到的是**假差异**。

⇒ 采集类项目里，**「相邻页比较」本身就是一次 A/B 比较**，因而受同一条纪律约束。
这一点在纪律原文里没有明说（它写的是二进制/脚本的 A/B），而**站点内容会漂**这件事让它同样适用。

### 比记错一个数字更糟的地方

Leader 是在**同一天、同一份文档里批评「引用未验证数字」**之后，用违反基线纪律的方法造出这个假观测的。
而且它不是「引用了别人的错数」——**它被当作「我亲自实测的」用来推翻别人的数据**，这给了它额外的权威。

⇒ **「我亲自测的」不等于「我测对了」。** 第一手观察也有它自己的失效模式，而这种失效**不留任何痕迹**：
输出里全是具体日期，看不出它们来自两个不同的时刻。

### dev 阻止了传播链的第四层

Leader 曾要求 dev 把「1 反例（p147→p148）」写进代码注释。dev 拒绝并指出：

> 那正是你这条消息自己描述的那条传播链：`reviewer 的实测 → 你的 DoD → 我的代码注释`。
> 如果我照办，这条链就变成**四层**，而且新写进去的「1 反例」我刚复现不出来。

**它识别出 Leader 正在重复 Leader 刚刚批评过的那件事。**

### 判据为什么最终保持不变（理由来自 dev，比 Leader 原本的强）

Leader 原本还想用「完整性判定归 TASK-008」这个设计论证来降级它。dev 的反驳成立：

> 那个论证针对的是**完整性判定**（漏了谁），而这条守卫做的是**页序自洽性判定**（序乱没乱）——
> 后者是**当场可判的事实，不需要知道漏了谁**。翻页层报「序乱了」、对账层报「少了哪几期」，两者不冲突。

⇒ `delta < 0 ⇒ 硬报错` 保持；`delta == 0`（同日跨页，实测占 50%）必须放行。
最终分布以 **test-agent-27 的独立实测**为准 —— 不采用 Leader 的、也不采用 dev 的。

### 元凶是一个 idiom，不是「Leader 不小心」

```bash
[ -f "p$p.html" ] || curl -s -o "p$p.html" ...   # ← 就是这一行
```

`|| curl` 的缓存语义在「**反复调试同一个脚本**」时是对的（不重复打网络），
在「**采一份基线快照**」时是错的（新抓的页与几小时前的旧页混在一起）——**而同一行代码看不出区别**。

⚠️ dev-agent-55 写那 22 对时**写的是一模一样的一行**。它没被坑到纯属运气：
那个共享 scratchpad 目录里已有别人的 52 份 `p*.html`，它看到「抓取完成: 52 页」（期望 23）
觉得数不对才去查。**换个空目录它会得到和 Leader 一样的混合快照，并且同样不会察觉**
——因为跨时间混合的快照，**从内容上看完全正常**。

⇒ 这是**结构性陷阱**，不是个人疏漏。别把处方写成「小心点」。

### ✅ 采样自证不变量（dev-agent-55 提出，Leader 实测命中）

```
唯一 article_id 数  ==  页数 × 每页条数
```

**原理**：若抓取窗口内站点移位（新文上架把条目往后推），**边界那篇必然同时出现在相邻两页**
——它在旧页已被抓到、在新页又出现一次 ⇒ 唯一 id 数 < 总条数。

**两组对照都有，缺一不可**（只有阴性一侧时，它与「恒返回干净」的假守卫在观测上无法区分）：

| | 快照 | 结果 |
|---|---|---|
| **阳性**（Leader，已知有移位） | 跨 2h16m 混合抓取的 p136–p158 | 总 345 / **唯一 343** / **重复 2 个，均在 p145–p146** ⇒ **命中** |
| **阴性**（dev-agent-55，7 秒内抓完） | 同区间 p136–p158 | 总 345 / **唯一 345** / **0 重复** ⇒ 正常放行，**不误报** |

⇒ 它**比时间戳证据更本质**：时间戳只说明「抓取跨了时间」（成因），
不变量证明「**内容确实移位了**」（后果），且**不需要知道成因**——
换一种成因（并发窗口内站点更新、CDN 节点不一致）它照样命中。
**重复出现的位置还直接指出移位发生在哪个页边界**，这一点时间戳给不了。

### ⚠️ 它是**单向**判据，抓不到跳页

它只能抓到**「某篇同时出现在相邻两页」**这一个方向：**条目新增 ⇒ 内容下移 ⇒ 边界那篇重复**。

**反方向抓不到**：条目**下架** ⇒ 后续前移 ⇒ **整页被跳过**。那种情况**不产生任何重复**，
唯一 id 数照样等于 `页数 × 每页条数`，不变量全绿。

### 🔴 订正：`boundary[3]` **也**抓不到跳页 —— 两者同向，不是互补

**本节曾写「不变量管下移、`boundary[3]` 管前移导致的跳页，两者互补」——那半是错的**
（test-agent-27 用探针直接观察推翻，见 `docs/04-test/TASK-002-verification.md:101`：
构造「p2 拿到本该在 p3 的那一页、整整 15 条被略过」⇒ 守卫**完全沉默、静默放行**）。

必然如此：**下架 ⇒ `p(N+1).newest` 变老 ⇒ 判据更满足 ⇒ 永不触发。**

**正确的三行表**：

| 守卫 | 抓的方向 | 灵敏度 |
|---|---|---|
| 唯一 id 数不变量 | 内容**下移**（新增）⇒ 重复 | 插入 **1 条**即命中（边界那篇必然重复） |
| `boundary[3]` 连续性 | 内容**下移**（新增）⇒ 日期倒挂 | 需插入 **≥2 条**（插 1 条时 delta=0，放行） |
| **无人管** | 内容**前移**（下架）⇒ **跳页** | → 归 **TASK-008** 的完整性对账 |

> 口径（test-agent-27 标注）：上表灵敏度两行**均为构造与结构推导，不是观察到真实插入事件**。
> 「插 1 条即命中」是结构必然（边界那篇同时落在相邻两页）；「插 1 条 delta=0」对应三批实测里
> 同日跨页那 11 个取等号样本。

⇒ **推论与本节原文相反**：对它俩共同面对的那个方向，**不变量严格比 `boundary[3]` 更灵敏**。

### ✅ 它到底是什么：**列表移位（churn）检测器，且只对插入方向灵敏**

（dev-agent-55 提出定性、明确标注未验证且未擅自写进注释；test-agent-27 构造 5 个场景**直接观察**后确认，
并**收窄了两处措辞** —— 下面是收窄后的版本，`docs/04-test/TASK-002-verification.md` §四有全部观察数据。）

> 触发意味着「**列表在我们脚下动过，这次翻页跨了两个时间点**」，**而不是**「漏抓了数据」。
> 漏抓（下架方向）它看不见，归 TASK-008。

**「守卫从不在有数据丢失时触发」成立，且有结构性原因**（不只是实测）：

> 一次变动的净位移是**一个标量** ⇒ 每个页边界上「**重叠**」与「**缺口**」**互斥**。
> 触发 ⟺ 净插入 ⟺ 重叠；丢失 ⟺ 净下架 ⟺ 缺口。

实测五场景：净插入 +2 ⇒ 触发、无条目被跳过；净下架 −2 ⇒ **沉默**，且 `i4/i5 仍在列表却从未出现在任何一页`；
混合插3/下架1（净 +2）⇒ 触发；混合插1/下架3（净 −2）⇒ 沉默；净位移 +1 ⇒ 沉默（边界重复被去重吃掉）。

#### ⚠️ 两处被验证者收窄的措辞（不收窄就又是一句没验过的声称）

1. **「触发时无数据丢失」须限定为「没有任何*扫描开始时就已存在*的条目被跳过」。**
   净插入时那几篇**新上架**的文章落在游标上方，本次扫描永远取不到 —— 这是**任何单遍翻页的固有性质**，
   与本守卫无关，且回填目标是历史数据、不构成实际问题。**但话不能说成「无数据丢失」。**
2. 🔴 **「触发 ⇒ 列表正在 churn ⇒ 别的边界可能是净下架（有丢失）」这一步推理弱，已弃用。**
   守卫检测的是**插入**型 churn，而丢失来自**下架** —— 两者是**不同事件**，频率相差很远
   （实测上架约 1 篇/7 分钟；撤回是罕见事件）。**观察到插入，对下架的概率几乎没有信息量。**
   ⇒ 改用不依赖这步推理的理由：**触发 ⇒ 这份 manifest 混了两个时间点 ⇒ 重跑。** 该理由自身成立。

⇒ **硬失败仍然合理**：触发条件罕见（需相邻两页抓取间隔内插入 ≥2 条，vs 实测速率约 1 篇/7 分钟、
回填约 3.6 秒/页），不会烦人；而「manifest 混了时间点」本身就值得重跑。

⚠️ **代码注释尚未同步这段定性**（`backfill_scan.go` 不在任何在途任务的 `writes` 内，
为一句注释走一轮返工不成比例）⇒ 已登记给 **TASK-007** 写进 CONTRACTS。

### 那么为什么仍要保留 `boundary[3]`

**不能**用「它管跳页」来支撑——那条理由是假的。真理由有两条：

1. **页序自洽是当场可判的事实**，不需要知道漏了谁（原 dev-agent-55 的论证，成立）；
2. 它在**真跑过程中就地生效**，而不变量是**离线采样检查** —— 两者的生效时机不同。

⚠️ **这段订正本身就是一次实例**：Leader 在同一天内先写下「矛盾的两半共存时，先读到哪半是随机的，
而错的那半看起来和对的一样可信」用以表扬验证者订正自己的记忆，**然后在 20 分钟内于两条消息之间
制造了同一个矛盾**，并把错的那半写进了本节。发现它的是验证者，不是 Leader 自查。

### 给后来者的操作要求（三条，缺一不可）

1. **同一时刻并发抓完整批**：`for p in ...; do curl ... & done; wait`
2. **不要用 `[ -f ] ||` 跳过已存在的文件** —— 采基线时必须每次都抓
3. **抓完先跑自证**，三项全过才可用于任何跨页比较：
   - `唯一 article_id 数 == 页数 × 每页条数`（无移位）
   - 每页条数 == 该页 `istitle="true"` 计数（解析完整）
   - 每页页内严格单调递减（页内有序）
