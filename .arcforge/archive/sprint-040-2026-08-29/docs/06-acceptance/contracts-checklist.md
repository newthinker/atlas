10. 🔴 **求和自洽校验挡不住「错分」，只挡得住「漏项」**（test-m1c3a-v1 自我更正时发现，Leader 复核）：

29. 🔴 **「分支有 commit 而 master 没有」这条活性判据有一个静默漏检**（Leader 实撞）：

    长期记忆里记着一条补活性缺口的建议：`git branch --list 'task/TASK-*'` 逐条
    `git rev-list --count master..<branch>`，「分支有 commit 而 master 没有」= 有人在等 merge。
    **Leader 照做时漏掉了正在等 merge 的那个任务。**

    **根因**：`git branch --list` 对**在 linked worktree 中 checkout 的分支**用 **`+`** 前缀标记
    （不是 `*`）：

    ```
    [  task/TASK-004-m1c3a]     ← 普通分支，两个空格
    [+ task/TASK-005-m1c3a]     ← 正被 worktree 占用
    ```

    循环里写 `tr -d ' *'` 只删空格和 `*` ⇒ 分支名变成 `+task/TASK-005-m1c3a`
    ⇒ `git rev-list` 失败（stderr 被吞）⇒ `n` 为空 ⇒ `[ "$n" -gt 0 ]` 报错并跳过该条。

    🔴 **失效方向最坏**：它**专门漏掉正在被 worktree 使用的分支**——
    而「dev 刚提交、worktree 还没拆、正在等 merge」恰恰**总是**这种状态。
    ⇒ **这条判据在它最该起作用的场景下恒失效**，且输出看起来完全正常（其它分支照常列出）。

    🔴 **规则要写准（dev-m1c3a-a 实测后纠正，Leader 原写法过窄）**：
    问题不在「必须改用 `for-each-ref`」，而在「**别用默认输出再剥前缀**」。
    dev 建临时 worktree 占住分支复现 `+` 前缀，三种写法并排实测：

    ```
    A  git branch --list 'task/*' | tr -d ' *'                 → [+task/…]  rev-list 失败 ← 踩坑
    B  git branch --list 'task/*' --format='%(refname:short)'  → [task/…]   ✓ 安全
    C  git for-each-ref --format='%(refname:short)' refs/…     → [task/…]   ✓ 安全
    ```

    根因：**`--format` 会整行替换、不输出前缀标记**。⇒ B 与 C 都安全。
    原写法会让已经在用 `--format` 的人以为自己也得改。

    **修法**：任选 B 或 C；**要避免的是 A**（默认输出 + 手工剥前缀）。

    ⚠️ 同族：本 Sprint 记过的「shell 静默失效」——命令跑了、退出码正常、输出合理，
    **但漏掉了整整一类对象**。这次的特殊之处是**被漏掉的正是判据要找的那一类**。

30. 🔴 **「内容判据」也有时效性：全文件 `diff` 不能长期用作「已合入」的证明**（Leader 实撞）：

    本 Sprint 反复强调「判『进去了没』用内容判据，别用 `merge-base`」。但**内容判据本身分两种**：

    | 形式 | 时效性 |
    |---|---|
    | `git diff <旧 sha> master -- <声明路径>` 为空 | 🔴 **只在 master 未被他人改动时成立** |
    | `grep -c '<该交付独有的字串>'` | ✅ 长期有效 |

    **实例**：`55a5fef`（TASK-002 的注释订正）的内容早已由 `bca01bd` 合入 master，
    Leader 当时用全文件 `diff` 验证为空。**两天后（TASK-004 合入后）同一条命令输出非空**
    ——因为 TASK-004 也改了 `extract_test.go` 的那段注释。

    ⇒ 全文件 diff 回答的是「这两棵树在该路径上是否逐字节相同」，
    **不是**「那份交付的内容是否在里面」。master 每前进一步，前者就更可能为假而后者不变。

    **正确判据**（本例）：`git show master:internal/hestia/extract_test.go | grep -c SURVIVED` = 1
    （`SURVIVED` 是那次订正引入的独有字串）。另两条对照：`四道互相独立` = 1、假声明 `两格必须转红` = 0。

    ⚠️ 这是「判据形式正确、但指向的对象不对」在本 Sprint 的**第四个**变体
    （前三个：作废的中间 sha / 不区分版本的特征 / 作用域过宽）。
    共同点：**判据本身没错，错在它回答的问题不是我要问的那个**。
