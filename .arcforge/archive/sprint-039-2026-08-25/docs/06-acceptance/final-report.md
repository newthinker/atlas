# 六、机制层发现（本 sprint 的副产物，值得单独看）

详见 `.arcforge/docs/03-progress/plan.md`（1112 行）与 `.arcforge/wisdom/_digest.md`（1274 行）。
以下四条是**框架层**的，不是本项目特有的：

## 1. 🔴 「写权可达性」：`writes` 路径的合法写者可能不含任务 owner

TASK-005 的 `writes` 指向 `docs/06-acceptance/*`，而矩阵里该路径的合法写者是 `["leader"]`
⇒ **任何 dev 任务都不可能自己满足这条 `writes`**，而 **validator 查不出来**
（它查 scope 互斥与非空，**不查写权可达性**）。

**这次靠 Leader 代写绕过，但下一个同形任务会原样再撞，且撞时多半已 `in_progress`、DoD 改不动。**

⇒ **可做成 validator 规则**（纯静态、零成本，Leader 已写出 15 行原型并实测只逮住那一条、零误报）：

    for path in writes:  assert role(assigned_to) ∈ rules[path].writers

⚠️ **但它只覆盖这一类**。本 sprint 四个「结构上无法完成」里另外三个
（要改的文件不在 `writes` 里 / DoD 要的数据结构上不存在）**要先知道「实现这条 DoD 得动哪些文件」，
那是 dev 开工后才知道的 ⇒ 做不成 validator 规则，只能靠派发后的 dev 预检。**
⇒ **预检不是 validator 的替补，它覆盖的是 validator 结构上够不着的那一类。**

## 2. 🔴 Leader 侧 8 小时 25 分静默，**没有任何机制发现它**

    Leader 最后一次写 transitions.jsonl   2026-08-24T15:01:50Z
    TASK-004 的 merge commit              2026-08-24T23:27:19Z    缺口 8h25m

期间 dev 交付完成、发三条消息、零回复；任务停在 `in_progress`（它**拒绝**转假 `dev_done`），
而 **`stale-dispatch` 对 `in_progress` 刻意不设阈值** ⇒ validator 全程沉默。

| 谁 | 能做什么 |
|---|---|
| validator | ❌ 不覆盖 `in_progress` |
| idle hook | ❌ 只会催「推进到 `dev_done`」——本 sprint **三次**把 dev 指向错误动作 |
| git 分支判据 | ⚠️ **候选过滤器，不是状态区分器**（对在途提交同样报警） |
| dev | ❌ `in_progress` 出边里没有 `dev-*` 能到 `blocked_human` 的 |
| **Leader** | ✅ **唯一能解的，而卡住的正是 Leader** |

⇒ **本 sprint 唯一一个结构上无人可解的活性缺口。**

## 3. 派发前预检是本 sprint 最高产的动作

**四次预检，各逮到会卡死人的东西**（TASK-003 数字过期 / TASK-004 结构死锁 ×2 / TASK-005 过期指令 + 锚分类错）。

⚠️ **Leader 自己预检只找得到自己想得到的那一类**（数字过期、指令过期、分类错）——
**四次里没有一次是「这条 DoD 要的东西结构上不存在」，那两条都是 dev 预检出来的。**

⇒ **每个任务派发前，让一个空闲实例做只读预检。窗口只在 `pending` 期间开着。**

## 4. 「仪器骗人」这一族本 sprint 撞了**五次**

| # | 仪器 | 输出 | 怎么被发现 |
|---|---|---|---|
| 1 | `xargs GOTOOLCHAIN=local gofmt -l` | 空 + exit 0 | 与已知的 28 矛盾 |
| 2 | `awk` 只匹配缩进 0/4 | 1219 | 与 grep 的 1231 矛盾 |
| 3 | `grep -cE '…+…'` / `grep -cF '^…'` | 0 | 内容明明写了 |
| 4 | `lstrip("./")` 剥字符集 | **零输出** | **靠人主动追** |
| 5 | `$1=="-"` 误收 3 行 | 57 | 与报告写的 54 矛盾 |

⇒ **五次里四次靠「与另一个已有的数矛盾」发现，只有一次靠主动追。**
⇒ **没有等式可对的数字，其错误率无法估计** —— 第 4 例最险，因为「零输出」**没有任何东西可以与之矛盾**。

**可执行**：
- 任何「零/空」结果，先问「**如果命令本身没跑成，输出会是什么？**」——若答案也是空，那个空不构成证据；
- **报「没有命中」的检查，必须同时报「检查了多少个对象」** —— 只报前者时，分母为 0 与分子为 0 长得一样。
