⇒ **新增一个 24 个月的相邻对**。

**第三步 —— 量级：用本 sprint 自己测出的增长率算，这两个缺口都会翻过 0.15。**

**第四步 —— 更要紧的是反方向那一半（标定被污染）**

### R2-02 [MEDIUM] `groupUnsupported` 的防御在同一份输出里被 `writeParseFailures` 抵消：报告 70% 的行是同一句话

**file:line**：`internal/hestia/calibrate.go:363-366`（`groupUnsupported` 的注释）
vs `internal/hestia/calibrate_report.go:224`（`writeParseFailures(w, "本迭代不解析（不是失败）", res.Unsupported)`）

**证据类型**：**跑出来的**（直接数真跑产物 `.arcforge/docs/06-acceptance/calibrate-report.md` 内嵌的 280 行 CLI 输出）

`groupUnsupported` 的注释把理由写得毫不含糊：

> 不逐篇打：真语料上 monthly 约 53 篇，逐篇打就是 53 行同一句话，把另外几行淹掉
> ——而「淹掉真信号」正是这一格与失败表分开的理由，**在渲染层再犯一次就白分了**。

**而渲染层正是再犯了一次**，且规模大了近 4 倍。实测（相对行号以内嵌输出首行为 0）：

| 内容 | 位置 | 行数 |
|---|---|---|
| `groupUnsupported` 归并版（`69 × […] / 69 × […] / 55 × […]`） | 3–5 | **3** |
| 真·解析失败 3 条（第一次，`writeCollectSummary`） | 7–9 | 3 |
| 真·解析失败 3 条（**第二次**，`writeFailureSection`） | 81–83 | 3 |
| **逐篇展开的「本迭代不解析」** | ~85–278（**直到输出末尾**） | **193** |
| 合计 | | **280** |

⇒ **193/280 = 69% 的输出行是同一句话**，且它紧跟在真失败清单后面、一直铺到结尾。
`groupUnsupported` 想保护的那 3 条真失败，正被它保护不到的那一段淹掉。

**成因是架构性的，不是笔误**：`Calibrate` 顺序调 `collectSamples`（内部 `writeCollectSummary`）
与 `renderCalibrateReport`（内部 `writeFailureSection`），**两者写同一个 `d.Out`，且渲染的是同一批数据**
—— 四格去向、fetch 失败、解析失败**全部各打一遍**，只是一个归并、一个逐篇。
两个函数各自的注释都说得通，**没有任何一处注释提到另一处的存在**。

**建议**：`writeFailureSection` 对 `Unsupported` 改用 `groupUnsupported`
（`writeParseFailures` 保留给 `Failures` —— 那一格逐篇打是对的，成因不同要分工）；
或让 `Calibrate` 只保留一处渲染。⚠️ 顺带：这也会把报告从 280 行压到约 90 行，
对已知发现 V6（跳读者路径）是**同向**改善。

### R2-04 [LOW] `CalibrateResult.Periods` 是派生量却独立维护 —— 与本包自己刚立的原则相悖，且无不变式测试

**file:line**：`internal/hestia/calibrate.go:152`（`res.Periods++`）、`:65`（字段注释）

`collectSamples` 的循环里每一篇**恰好**落进 `Records` 或 `Failures` 之一（四个 `continue` 分支全是

而同一个函数在 `:200` 刚刚为「同一事实不留两份副本」把 `Samples` 改成由 `Records` 派生，
注释写「两份副本会各自演化」。⇒ **`Periods` 正是那个原则的例外，且没有注释解释为什么例外。**

**危害**（推导，未发生）：将来加第五个 `continue` 分支（如「跳过重复期次」）而忘了不变式，
`Periods` 与实际去向就对不上，而它是报告表头「尝试解析 %d 期」与那句「可用样本为 0」错误里的数
—— **两处都是给人看的解释性数字，错了不会有任何东西报错**。
测试侧现有 4 处断 `Periods` 的具体值（`:105 :135 :207 :259`），**没有一条断不变式**。

**建议**：删字段、改成 `func (r *CalibrateResult) Periods() int { return len(r.Records)+len(r.Failures) }`；
或保留字段但补一条不变式断言。⚠️ 改导出面要注意 `store_test.go` 的精确相等名单（`CalibrateResult` 未导出方法则不受影响）。

### R2-06 [MEDIUM] 全仓唯一的下游完整性校验，实际只覆盖 **25/218 = 11.5%** 的产物，而报告不报这个分母

### R2-07 [MEDIUM] 「可用样本为 0」这道闸，被一类输入**逐字**产出它注释里写的那个失效形态而照样放行

成因是两处口径不一致：`samplesFromRecords`（`:412-420`）把 `r.Values` 的**每一个**键都收进

「本文件反复出现的一条原则：**不让东西静默消失**」，并列了一篇文章的**四种**去向、
