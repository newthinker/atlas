## F8：`require.NotErrorIs(t, errors.Unwrap(err), err)` 平凡为真（test-agent-24 决定性实验）

`store_test.go:1674`（TASK-003 交付）。**注释写的本意与代码的行为不一致**：

```go
// 注释：要的是「包住」，所以额外断言 Unwrap 后还剩东西、且外层不等于内层。
require.NotErrorIs(t, errors.Unwrap(err), err)
```

不包裹时 `err` 就是裸 sentinel ⇒ `errors.Unwrap(err)` = `nil` ⇒ `errors.Is(nil, x)` **恒 false**
⇒ 该断言**在它本该抓住的那个场景里恒过**。三次消融（B1/B2/B3）中它一次都没红。

**决定性实验**：同一变异下只把它换成注释所声称的本意 `require.NotNil(t, errors.Unwrap(err))`
⇒ **立刻致红**（`Expected value not to be nil.`）。本意的断言有杀伤力，写下的那条没有。

**不构成 DoD 失败**（三个实质要求分别由 `:1666` / `:1668`+`:1675` / `:1669`+`:1670` 守住，
B1/B2/B3 全 KILLED），故 TASK-003 判 PASS。但 discovery `key_findings[3]` 两处失实：
(a) 写下的代码并不断言「Unwrap 后仍有内层」；(b)「A6 消融确认**这组**断言在守卫」不成立
—— A6 是被 `:1668` 的 `assert.ErrorIs` 杀的。**结论对、理由错。**

⇒ **断言「包住了」的正确写法是 `require.NotNil(t, errors.Unwrap(err))`。**
已转达 dev-agent-46（discovery 随 `verified` 冻结改不了，只能靠转达 + 报告留档）。

**这条的通用形式**（值得记住）：比事后消融更早生效的问法是——
> **有没有一个我想排除的实现，能让这条断言照样绿？**

`errors.Is` 证不了「包住」，正因为**不包裹的实现也能让它为真**。dev 当时已想到这一层
（才补了两条），但补的那条本身又中了同一个坑。**事后消融是补救，事前发问是预防。**
