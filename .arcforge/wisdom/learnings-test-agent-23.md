⇒ 验证者的自设变异价值在于**划清「测试覆盖边界」**，而非扩大退回面。

## test-agent-23 / TASK-004 验证（2026-08-10，被验 sha 65a4db0）

**8. 验证者自己的探针也会设计错，且错法与被验对象同源。**
我验「前缀理论」时第一版用全锚定 `^(.+?)(alt)([0-9.]+)(单位)$`，得出「加入前缀词后顺序仍无
影响」，与 dev 的理论矛盾。复查是**我的探针错了**：`$` 锚点 + 必须匹配的数字段会**强制回溯**，
短词分支匹配后无法收尾便回退再试长词，把顺序敏感性整个掩盖。改用**无锚点**形态后差异立刻
显现。⇒ **探针跑出「与被验方主张相反」的结果时，先怀疑探针**；尤其当探针比被验对象**约束更强**
（多一个锚点、多一段必须匹配）时，强约束会引入回溯这类掩盖效应。

**9. 「顺序即语义」在 leftmost-first 引擎里只对前缀关系成立，对后缀关系不成立。**
Go regexp 是 leftmost-first：交替顺序只在两分支能在**同一起始位置**都匹配时才有语义，也就是
一个是另一个的**前缀**时。本任务 DoD 断言「净融资 必须排在 融资 前」——但「融资」是「净融资」
的**后缀**，在「净」那个位置上压根匹配不上，顺序写反输出逐字节相同（20 组对照，差异 0）。
⇒ 见到「长词必须在前」这类要求，**先分清前缀还是后缀**；后缀关系下该要求是空的，
按它写出的测试**实现对错都绿**，是假防线。真正该守的不变量是「任意两项互不为前缀」。

**10. DoD 判据不可实现时，判 PASS 还是 dod_defect 退回，看「有没有 rework 可做」。**
本任务 boundary[0] 的字面判据不可实现（恒绿），按字面属 dod_defect。但 dev 已交付**严格更强**
的替代（真失效模式 + 真不变量各一条测试），且其中一条断言的正是 DoD 要的**后果**
（「企业债券净」匹配不上清单项），只是成因被 DoD 归错了。退回没有 rework 可做，只会白涨
rework_count。⇒ 判 **verified + 在报告和 inbox 里显著标注 DoD 缺陷并给出修订措辞**。
`rejected` 的目的是取得返工，**没有返工可取时它就是纯损耗**。

**11. 变异 harness 用 `if false {` 关掉分支会孤立 import ⇒ 编译错误 ⇒ 假 KILLED。**
我的 M6/M7 这么写，`strings`/`math` 变成未使用，vet 红。四条自证里的「vet 红即 INVALID」
挡住了它——否则会误记两个假杀。正确写法是**保持 import 仍被使用的恒假条件**：
`strings.HasPrefix(num, "\x00")`、`math.IsNaN(v) && math.IsInf(v, 0)`（不可能同真）。
⇒ 变异要改**语义**不能改**编译面**；这条对 Go 尤其要紧（未使用 import 是编译错误而非告警）。

**12. 静态扫描类测试必须自带「扫到了东西」的自证。**
dev 的 G6 测试扫包内非 _test.go 文件断言 `newAmount("` 零命中，并加 `require.NotZero(scanned)`
——扫到 0 个文件时「零命中」毫无意义。我用三个变异（改实现绕过、生产文件插入两种字面量调用）
确认它真会转红。⇒ 凡「断言某模式不出现」的测试，**必须同时断言搜索范围非空**，
否则它是一条永远绿的假防线（与「无 SURVIVED 即满分」同构）。

**13. `assert.Contains(s, "")` 恒真——用例集含空串时那条断言等于没测。**
dev 在 error_handling[0] 的用例里有空串方向词，改用 `strconv.Quote(dir)` 断言 `%q` 形态才是真
检查。⇒ 审测试时见到 `Contains(x, 变量)` 且**变量取值集合含空串/空切片**，直接判为假绿断言。
