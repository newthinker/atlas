
## test-agent-21 / TASK-002（2026-08-08）

### 1. 「正确的结论 + 错误的复现理由」是一类独立的失效模式

本次 TASK-002 判据②实撞。Leader 给的复现手法是「把 `period` 与 `period_type` 的校验**互换**」，
结论（别照抄 `assert.Contains` 这种弱断言）是对的，**但理由给错了**。dev-agent-42 发现并指出，
Leader 更正。我把两个方向都实测（同一 commit `a087b98`、同一 worktree、背对背，`go vet` 均 exit 0）：

| 组合 | 总计 | `period` 子测 | `period_type` 子测 |
|---|---|---|---|
| A) `Contains` + **单侧误写**（只把 `period` 标签写成 `period_type`） | **PASS=23 FAIL=0** | **PASS（假绿）** | PASS |
| B) `Contains` + **完整互换** | PASS=21 FAIL=2 | **PASS（假绿）** | **FAIL** |
| C) `EqualError` + **单侧误写** | PASS=21 FAIL=2 | **FAIL** | PASS |

机理：错误串 `"hestia: meta.period_type must not be empty"` **包含**子串 `"period"`，
故 `Contains(err, "period")` 恒真 → `period` 子测在**两个方向下都假绿**；B 里那条红来自
`period_type` **另一侧**，与要证的命题无关。

**危险之处**：B 方向的实验**看起来是成功的**（有红、有信号、可复现），验证者据此会推出
「Contains 也拦得住、DoD 这条多余」——**结论错，而实验本身一步没做错**。
这比「实验失败」隐蔽得多：实验失败会促人再查，实验「成功」直接终止追问。

**可迁移判据**：凡字段名存在**子串包含关系**（`period`/`period_type`、`id`/`id_type`、
`name`/`name_zh`、`user`/`username`），设计变异时必须用**单侧误写**，不能用互换——
互换会同时扰动两侧，让「未被扰动的那一侧」贡献一条与命题无关的红，掩盖真实盲区。

### 3. 「测试列了这个用例」≠「这个输入真的被拒」

DoD 点名了五类必测输入。我没有只确认测试文件里有对应字符串，而是另写一份**独立探针**

配合变异（删掉校验块 → 测试转红）才构成完整证据链：探针证**当前行为对**，变异证**断言在守**。

### 4. 写通道调用：`< /dev/stdin` 与 heredoc 不能同时用

`arcforge-write.sh ... doc <path> < /dev/stdin <<'EOF'` 会**静默卡到超时**（stdin 被抢）。
写通道头注释里就记着这个形态（`discovery <id> --file x 曾静默卡到超时`），我还是撞了。
正确写法二选一：**纯 heredoc**，或 **`< 文件路径`**（内容长时后者更稳，还能先 `wc -l` 自检）。
关键后续动作：卡死后**先直读目标文件确认有没有被写坏**——本次确认文件保持前一版完好（行数、
mtime、特征串三项比对），才敢重做。**别假设「命令没成功」等于「文件没变化」。**

## 「观察一致 ≠ 成因一致」这条纪律，我在自己不熟的对象上放松了一次(2026-08-08, TASK-002 收尾后)

**我做对的那次**：M10 变异首次尝试因 perl 转义写坏源文件、`go vet` 报 illegal character。
「编译失败的 KILLED」与「真 KILLED」在「测试红」这一层观察完全相同——我没把它计入战果,
换转义重做后才取有效结果。

**我做错的那次(同一天,相隔几小时)**：TASK-001 的 `verifier` 字段值是 `test-agent-20`,
恰好等于上一轮的残留值。我直接判定「leader 派发时没带 `--field verifier=`,残留值原样留下」。
实际上 leader **显式带了** `--field verifier=test-agent-20`(它是 P1 的发现者,复验自己报出
的缺口上下文最连贯)。**显式赋值与残留未覆盖,在文件终态上无法分辨。**

**可迁移规则**：这条纪律不会因为「我已经在别处用过」就自动生效。它在**自己熟悉的对象**
(变异/测试结果)上是肌肉记忆,在**不熟悉的对象**(他人的调度决策、他人的进程状态)上会退回
「从终态反推成因」。判据不该按对象亲疏切换 —— 凡是「我只看到终态」,就必须显式列出可能成因,
哪怕只有一条我认为极可能。

**同一 Sprint 里 leader 也犯了对称的一次**：他从我 3 小时零消息推断「已停机」,而真实成因是
「被 idle hook 唤醒 200+ 轮、每轮完整重扫、按去重规则不再发消息」——即**对 leader 不可见地
活着**。他不知道后一种成因存在。两次失误的形状完全相同,各自发生在对方的领域里。

⇒ 这也把那条 hook 缺陷的定性改了:它不止空转烧 token(可计量、止于浪费),还制造**沉默失效**
——没有任何输出会显示「有一个 agent 正在活跃地无事可做」,而 leader 据此改变了调度决策。
修法应在 hook 侧(`test-*` 分支加「且 verifier 未指定或指向本实例」),不要在症状层加信号:
被唤醒的 test agent 结构上无法消除唤醒条件(`dev_done → verifying` 是 leader 专属边),
加信号只会把「我又被叫醒、我又没事做」变成可见噪音。

## L: 「只改注释」有充分证明，不必靠读 diff 判断（@ TASK-007, 2026-08-09）

验「这个 commit 只动了注释、无可执行语句改动」时，读 diff 逐行确认是**必要不充分**的：
人眼/正则都可能漏掉一行藏在注释块里的语句，或误判字符串字面量里的 `//`。

充分的做法是**把注释消掉再逐字节比对**：

```
git show <before>:path.go | grep -vE '^\s*//' > a
git show <after>:path.go  | grep -vE '^\s*//' > b
diff a b        # rc=0 且 sha256 相同 ⇒ 非注释内容改动为空集
```

它把「看起来只改了注释」升级成「非注释内容的改动为空集」。TASK-007 用它得到两侧
sha256 `6953d02404e959c0…` 完全相同。**代价是一条命令，收益是从「判断」变成「证明」。**
（局限：整行注释过滤对「行尾注释」和「字符串里含 `//`」不成立，用前先确认文件形态。）

## L: 「契约而非机制」的约束应集中登记，而非散落在各自的注释里（@ TASK-007）

## L: `assert.Contains` 的针若来自被测输入，先确认固定文案不会顺带满足它（本包第 3 次，@ TASK-005 返工）

三次同形：T2 `error_handling[0]`、T3 O-1（`Contains(ddl,"period")` 被相邻的 `"period_type"` 吞掉）、
本次 C2「回显原串」六条断言里 **2 条重言式**——
`Contains(err,"fail")` 被错误模板里的 want-list 字面量 `"failed"` 满足；`Contains(err,"")` **恒真**。

共同机制：**针是被测输入，草垛里却有一段与输入无关的固定文案恰好含有它**。
断言因此在实现被改坏后仍然绿，而且**恰恰在最难诊断的输入上失效**（零值、词形错拼）。

发现手法：**做一个「只删掉那件事」的变异**（这里是移除 `%q` 原串回显，保留其余错误文案），
看红了几条。红的条数少于用例数，差额就是重言式；再把变异体的实际错误串打出来逐条比对，
就能指名是哪个固定片段吞掉了针。

修法通例：把针从裸输入换成**带上下文的整片段**（`fmt.Sprintf("%s=%q", id, input)`），
让针不可能出现在固定文案里。

## L: 「变异编译不过」先换写法，别急着记 INVALID（收下 test-agent-20 的 N2 更正，@ TASK-005 返工）

我的 M4（对调两个 `if` 块的顺序）第一次用的正则贪婪匹配，误命中了同文件的 `checkValues`，
`go vet` 报 `undefined: failed`。harness 按设计判 INVALID——**判得对，但如果就此收工，
换精确锚重做出来的 M4' 那条存活变异就会被漏掉**，而它正是本轮唯一的存活变异。

⇒ INVALID 是**关于变异写法**的结论，不是关于被测代码的结论。
「这个方向测不了」只能由**有效变异**得出；编译失败只能得出「这次写法不对」。
每一条 INVALID 都欠一次重写，重写不出来才是结论。
