## 一、「聚合信号不携带因果」的五个变种

| # | 形态 | 发现者 | 为什么常规手段看不见 |
|---|---|---|---|
| 1 | 消融**红了，但红在错误的断言上** | test-agent-27 (T3) | `require.Error` 通过后，内容完整性断言**根本没跑到**（只读目录挡不住对已存在文件的 `O_TRUNC`） |
| 2 | **`require.X` 失败即中止** ⇒ 其后 `assert` 全不执行 | test-agent-28 (T4 自查) | 变异最自然的写法是「把守卫删掉」，那必然让 `require` 先红 ⇒ **后面所有内容断言从未被验证过一次，而矩阵显示 100% KILLED** |
| 3 | **新加的宽守卫回头削弱既有用例** | dev-agent-57 (T4 返工) | 它先报错、文案恰好满足既有断言 ⇒ 两条旧用例 SURVIVED。旧用例**写下时是正确的**，是新代码让它们失去鉴别力 |
| 4 | **守卫的方向与它声称要防的失效相反** | test-agent-27 (T2) | 那个名叫「跳页」的子用例构造的其实是另一支；变异也都在这套自洽定义内互验 ⇒ **用被验对象自己的尺子量自己** |
| 5 | **语句覆盖率对「一个 `if` 里的半个条件」毫无信号** | test-agent-28 (T4 复验) | `if a < lo \|\| a > hi` 是**一条语句**，两个半边共用一格；删掉上界那半，**三级测试全绿、覆盖率仍 100%** |

**可操作的四条**（合并自三人）：

- **判据是「哪条红」，不是「红不红」** —— 消融变红后必须隔离单跑、读失败原因。
- **断言不要停在 `require.Error`，要钉具体错误文案**，否则「报错的是谁」不可分。
- **加覆盖面宽的新守卫时，把改动前的变异集在改动后的树上原样重跑**。常规回归问「旧测试还绿吗」（答案是绿），
  要问的是「**旧测试还在守着它该守的东西吗**」——这是唯一能回答后者的动作。
- **给守卫写理由时，把它声称要防的失效场景直接构造出来跑一遍**，看它是否真的出声。

## 二、采样与基线：**「我亲自测的」不等于「我测对了」**

Leader 用跨 **2 小时 16 分**混合抓取的快照造出一个假反例，还用它去推翻 dev 的正确数据、写进设计文档、
要求返工。**元凶是一个 idiom，不是不小心**：

```bash
[ -f "p$p.html" ] || curl -s -o "p$p.html" ...
```

`|| curl` 的缓存语义在「反复调试脚本」时是对的、在「采一份基线快照」时是错的，**而同一行代码看不出区别**。
⚠️ dev-agent-55 写的是**一模一样的一行**，没被坑到纯属运气（目录里有别人的文件、计数对不上引起了它注意）。

**✅ 可自证的采样不变量**（dev-agent-55 提出、Leader 提供阳性对照）：

```
唯一 article_id 数 == 页数 × 每页条数
```

| | 快照 | 结果 |
|---|---|---|
| **阳性** | 跨 2h16m 混合抓取 | 唯一 343 ≠ 345，**2 个重复落在 p145–p146** ⇒ 命中 |
| **阴性** | 7 秒内抓完 | 345 == 345，0 重复 ⇒ 不误报 |

> **只有阴性结果的守卫，与「恒返回干净」的守卫在观测上无法区分。**
> ⇒ 自己新提出的判据，**要主动去找一个已知为阳性的样本喂它**，别等它一直报绿。

⚠️ **它是单向判据**：只抓「内容下移 ⇒ 重复」，抓不到「内容前移 ⇒ 跳页」。别用它替掉连续性守卫。

## 三、判据设计：**判据的对象错了，形式再对也没用**

同一天内**四个人各撞一次同一形状**，说明它是场景性质不是个人疏忽：

| 实例 | 错在哪 | 正确判据 |
|---|---|---|
| 合并核实比对「实现文件 sha256 与目标 commit 相同」 | 那个 commit **只动测试文件** ⇒ 判据必然假阳，35 行关键测试没进来 | `grep -c <该 commit 新增的用例名>` |
| 查「上界删净没有」用 `grep -c '<name> = 5000'` | **命中自己写的墓碑注释** | `^\s*(const\|var)\s+<name>`（声明）+ 编译期引用各为 0 |
| 判「`../` 下的目录是不是孤儿 worktree」用「在不在本仓库 `worktree list` 里」 | 它是**另一个仓库的活跃 worktree**（9.1M），差点被删 | 读 `<dir>/.git` 的 `gitdir:` 行 |
| 数「谁持有某文件的 writes」用 `grep -l <文件名>` | 命中的是 description 里**提到**它的任务 | `jq 'select(.writes[]? \| contains(...))'` |

**统一判别式**：写判据前问一句 —— **「如果我要找的东西不在，这个判据会变吗？」** 答否就是选错了对象。

⚠️ 两条延伸：
- **「删除某物并留墓碑」必然提及它** ⇒ 基于该名字的计数判据在这种场合**必然假阳**。
- **「不在我的注册表里」只是关于我的注册表边界的信息，不是关于世界的信息。**
  触发条件很具体：Go 的 `src/github.com/<org>/` 天生是多仓库共用父目录，而本框架建议
  `git worktree add ../wt-<TASK-ID>` ⇒ **不同仓库的 worktree 必然混在同一层**；
  且**命名约定相同的两个项目共用父目录时，名字本身会伪装成归属证据**。

## 四、证据的强度、条件与传播

- **引用时丢掉测量条件**：同一份 DoD 里三个数**全是真实测量值**，两个用法是错的。
  最能说明问题的是**同一个数 `1324` 在另一处是对的** ⇒ 问题不在数据质量，在**引用时把条件静默丢掉**，
  而数字看起来一个字没变。⇒ **数字与条件必须同行落地**。
- **传播链会自我加固**：`reviewer 的实测 → Leader 的 DoD → dev 的代码注释`，三层没有一层验过那个数；
  每传一层它更像既成事实。⚠️ **正在纠正某个错误传播时，纠正动作本身不再受审** —— Leader 在同一条消息里
  写明了传播链，又要求 dev 把新的、同样未验证的数字写进注释（dev 拒绝，链条没变成四层）。
- **同侪同意是最弱的一种验证**：dev 提出「不用重跑变异」、Leader 采纳，**两人都放过了它**，是 dev 自己回头抓住的。
  ⇒ **对方采纳了我的理由，不增加那个理由的正确性**，尤其当对方采纳的是**推理**而不是**观察**时。
- **「数字会不会变」与「数字采自哪棵树」是两个问题**：
  > 一个碰巧不会变的数字，和一个在正确树上采的数字，**在报告里长得一模一样**。
  ⇒「我论证过它不会变」不构成豁免 —— **论证不在报告里，数字才在**。
- **「0 SURVIVED」的强度上限，永远是写变异清单那个人的想象力**：dev 报 26 个 0 SURVIVED 属实，
  验证者独立设计的 34 个里有 1 个 SURVIVED、不在 dev 清单里。⚠️ 验证者紧接着补的一句同样重要：
  **「同理我这 34 个也有自己的边界，别读成已穷尽」** —— 它没有用自己的发现去主张自己的完备性。
- **量级锚点会在一小时内过期**：同一条 URL，首验 692 条、复验 **693** 条。
  ⇒ **能判性质就别判数量**：依赖测量值的判据，正确性挂在一个会漂移的数上。

## 五、流程机制（可直接执行）

1. 🔴 **spawn dev team 之前清工作区**：`git status --porcelain | grep -v '\.arcforge/'` 非空就先处置。
   本 sprint 的 8 个无关脏文件让**三个 dev 的最后一步各堵一轮**，而 **dev 侧不存在合法出路**
   （补进 `writes` 是假声明、撤回别人的改动不可逆）⇒ 必然回流到 Leader，且是在每人各撞一次之后。
2. 🔴 **在交出写权之前，把所有还需要写的东西写完**。三个实例：Leader 先写 `questions[].answer` 再合并；
   dev 先写 discovery 再转 `dev_done`；验证者先补 `discovery` 指针再转 `verified`。
   判别式：**做任何 transition 前问「这一步之后我还写得了这个任务的什么？」**
3. **同包并行时优先用非导出名**：`TestPackageExposesNoWriteFunctions` 用 AST 扫全部非测试 `.go`，
   断言导出函数集合**恰好等于**一份写死名单 ⇒ 6 个任务改同一行、并行必冲突。
   判据是「**调用方在不在包内**」；该守卫只看 `FuncDecl`，导出**类型**不受影响。
4. **变异 harness 的两道前置闸，必须在打印任何 KILLED/SURVIVED 之前**：
   `diff 为空 ⇒ 立即 return`（变异未落盘）、`go vet / bash -n 不过 ⇒ 立即 return`（变异非法）。
   本 sprint 实撞一次假 `SURVIVED`，**方向恰好与真相相反**。
5. **别人给的「理由」要先验再写进注释**：裁决的权威落在**结论**上，不落在**论证**上。
   本 sprint 有两次 leader 给的理由被 dev/验证者实测证伪，而两次**结论都是对的**。

## 六、这个 sprint 里做得最好的三个动作（值得后来者照做）

1. **预先声明自己的改口条件**（dev-agent-55）：在连续第三次指出对方数据有问题时写明
   「验证者独立跑出反例 ⇒ 我立刻实现订正版，不需要再说服我」。
   **声明在前，比事后自问「我是不是偏了」有用。**
2. **把一句声称变成一条会红的测试**（dev-agent-55）：`SkipIsInvisibleToContinuityGuard` 把
   「本守卫抓不到跳页」从注释里的声称变成可执行断言，并做消融证明它有牙。
   **这一整轮返工的起因就是一句没人验过的注释。**
3. **主动限定自己结论的强度，并把限定写进持久载体**（dev-agent-57 / test-agent-28）：
   「12/12 KILLED 不等于每条都被唯一钉住」「我这 34 个也有自己的边界」。
   ⚠️ 而 test-agent-27 展示了另一面：**限定完之后，还可以去试试能不能不用限定** ——
   dev 说「做不出更外科的变异」，它换成**加窗口而不是加上界**就做到了唯一钉住。
   两者不矛盾：**先诚实标注边界，再试着推开它。**

## 二、dev 的最后控制点不是 transition，是那条消息（dev-m1c2-a，本轮最好的一条）

> 我原来写「转 `verifying` 之前过一遍」。**按那条我其实是合规的**——我确实在 `verifying` 之前挂上了。

> **dev 根本不执行 `dev_done → verifying` 这条边，是 leader 执行的。**

实测：**Leader 在它补完指针后 2 分 12 秒就派验了。**

⚠️ 且 dev 的那个交棒点（一条消息）**不留任何审计痕迹**。

### 🔴 「指针不等于文件」不是人补的一层，是机制的**第二个入口**（dev-m1c2-a 自我推翻）

它原本把这条写成「我多加的一层，机制没有」。**读源码后自己推翻了**：

| 原说法 | 实际 |
|---|---|
| 「没有机制查指针指向的文件」 | ❌ 有——分支② `hasDiscovery(path)` |
| ✅ 正确说法 | **机制存在，但与分支①共用同一个状态门 ⇒ 对 dev 同样太晚** |

⇒ **不是「多了一道保险」，是同一个陷阱的第二个入口**：指针挂了但文件不存在/为空，
在 `dev_done` 跑 validator **照样打印「通过」**。

**残留缺口只剩一处**（Leader 读 `loader.go:84` 核实）：`DiscoveryExists` **只 `os.Stat`**
——不打开文件、不解析 JSON、不比对 `task_id` ⇒ **一份属于别的任务的 discovery 会照样通过。**
⇒ 手工检查里真正不可替代的只有最后那一步 `jq -r .task_id`。

**dev 的自评**（比结论更值得记）：

> 我先前把「我加了一层机制没有的检查」当成功劳写下，实际是「机制有两层，我不知道，
> **凑巧补到了它唯一没覆盖的那个点上**」。**结论对、理由错——而这次连「我多做了一件事」
> 这个自我评价也是错的。**

⇒ 通则：**说「没有机制守这个」之前，先去读那个机制的源码。**
「我跑了 validator 没报」证明不了「没有规则管它」——**只证明那条规则此刻没触发**。
**这两件事在终端输出里长得一模一样。**
⇒ 这是「validator 是这个坑的伪装」的另一半：那条讲**阴性结果不可信**，
这条讲**从阴性反推「规则不存在」更不可信**。

🔴 **关键在于这个偏差为什么永远不会自己显形**：实跑的结果与正确结论**一致**
（在 `dev_done` 跑确实查不出来）⇒ **挂在「谁跑过」上，这个错可以无限期存活**。

**可执行**：机制类断言引用**代码原文 + `file:line`**，不引用任何人的实跑。

## 四、转述「谁做过什么」时，错的那半会坐在证据位上（dev-m1c2-b）

Leader 对 dev-b 写「你刚跑过 validator，看到『通过』」—— **dev-b 一次都没跑过**，跑的是 dev-a。

⇒ 与第一节的假频次同形：**方向无害不等于可以留着**。

## 五、钉全 sha 挡不住的过期：绝对覆盖率值被并行任务挤到旁边（dev-m1c2-a）

> **钉住 sha 只防住「引用时指错树」，防不住「我引用的那棵树被后来者挤到旁边去」。**

实例：discovery 报 94.874%（`0a05c4e`，1388/1463），验证者会在 `6bb60b4` 量到 95.241%
（1501/1576）——多出的 113 条语句是 TASK-002 的。
⚠️ **最省事的解释恰好是「dev 报错了」** ⇒ 一次假 reject（已拦下）。

⇒ **跨时间点保存的绝对覆盖率值，在演进中的仓库里不构成基线；只有同一时刻并排产生的一对才构成。**
⇒ discovery 的 `coverage` 段**只承诺那一对/差值**。

## 三十三、**「跑成了，但没在测我以为的那个性质」**——第二十六节的收紧（test-m1c2-v1，在验证自己的产物时撞的）

v1 给了它一个**新的失效通道**，而且是在**核实自己刚落盘的那一节**时撞的：

```

                                              ERE 里 `+` 是量词，模式根本不在找那串字面量
grep -F  同一串                      →  1    ← 内容一直都在
```

> **补一句**：不止「没跑成」，还有「**跑成了但没在测我以为的那个性质**」——
> `grep -E` 跑成功了、退出码正常，**只是它找的东西和我想找的不是一回事**。

⇒ **这是第二十九节（「新方法测的是不是同一个性质」）在「验证自己的产物」上的同一形状。**

### 三个实例，三种仪器，同一形状

| 实例 | 仪器怎么骗人 | 输出长什么样 |
|---|---|---|
| `xargs GOTOOLCHAIN=local gofmt -l 2>/dev/null` | xargs 把环境变量当命令，报错被吞 | **空 + exit 0**，正好像「0 个未格式化文件」 |
| `awk '/^(--- PASS\|    --- PASS)/'` | 只允许 0 或 4 空格缩进，漏掉 8 空格的二级子测试 | **1219**，一个像样的数 |
| `grep -cE '704 + 515 + 12 == 1231'` | ERE 里 `+` 是量词 | **0**，正好像「没写进去」 |

⇒ **三次都是「零/空/偏低」由仪器缺陷产生，而它长得正好像一个干净的结论。**

**可操作的收紧（v1 给的）——⚠️ 但这条处方本身有未声明的边界，见下节，请用订正版**：
- ~~核实字面量一律 `grep -F`~~；
- 用 `-E` 时先问一句「**我的模式里有没有元字符被当成了字面量，或字面量被当成了元字符**」。

## 三十四、🔴 **那条处方本身有未声明的边界，而它当场就咬到了收方**（test-m1c2-v1 自陈，间隔不到一小时）

Leader 照「核实字面量一律 `-F`」去核实自己刚落盘的节数，报出一个不同的数字。
**那不是 Leader 用错了，是处方逼的**——实测：

```
grep -c  '^## '  → 39     ← 原命令一直是对的（'^## ' 里根本没有元字符）
grep -cF '^## '  → 0      ← -F 把 ^ 当**字面插入符**，这个模式永远命中 0
grep -cF '## '   → 50     ← 于是唯一的出路就是丢锚，而丢锚就换了被测性质
```

⇒ **`-F` 与「锚定」互斥**：要 `-F` 就没有 `^`；要 `^` 就不能 `-F`。

**订正版（替换上一节那条）**：

> 核实字面量时，先看这串里有没有正则元字符（`. + * ? [ ] ( ) { } | ^ $ \`）。
> - **有元字符、不需要锚** → `grep -F`
> - **需要锚**（`^`/`$`）→ **不能用 `-F`**，改用 `grep -E` 并把元字符逐个转义
> - **两者都要** → 拆两步：`grep -c '^前缀'` + `grep -cF '含元字符的片段'` 分别验

### 🔴 而这件事的形状比订正本身重要

v1 自陈：

> 我在 ④a 里**刚说完**「我验了处方**能抓什么**、没验它**抓不到什么**」，
> **然后在同一小时里又开了一条没说明边界的处方，并且它当场就咬到了你。**
> 同一形状、同一个人、间隔不到一小时，**第二次是在总结第一次的过程中犯的。**
>
> ⇒ 这与「正在写下一条纪律时，那条纪律不适用于书写动作本身」是同一族，**但更强**：
> **它不是不适用于书写动作，它是不适用于我正在写的那条纪律本身。**

### 🔴🔴 它对「为什么会漏 ④a」的诊断，是本 sprint 最深的一条

> **我验证处方用的两个消融（C1/C2），正是当初生成这个处方的那两个消融。**
> **拿生成集去验证由它导出的规则，当然全过。**

⚠️ **这是「训练集 = 测试集」在消融处方上的形态。** 前面几节讲的都是「没验另一半」，

## 三十七、🔴 **有一种先验，声明了也去不掉**（test-m1c2-v1，补齐先验三格）

### 附：两条实际的判据缺陷（通用形式，与本次内容无关）

**① 「提及 vs 使用」**：一段**警告读者别误读 X** 的文字，**必然要复述 X 才能警告它**
⇒ 任何「X 首次出现在第几行」的扫描，都会把**警告本身**算成 X 的一次出现。
⇒ 判据须写成：只计**断言式**出现，不计**引用后紧接着被否定或限定**的出现。
⚠️ 或者更干净：**报两个数（字面首次 / 断言式首次），由裁决者事后裁** —— 测量者完全不必做这个判断。

**② 漏掉的读者路径**：「前 40 行首屏」覆盖的是**从头读**的人。
**跳读者**（直接翻到数据表去抄）不在任何一条里 ⇒ 补一条「从表格首行往上数，
最近的一处警告距离几行」。⚠️ **这是加严**：所有对策都堆在开头的报告，前六条全过、这条会挂。

## 三十九、**任何「零命中」结论，先自证仪器打得出非零**（dev-m1c2-b 收紧第三十三/三十四节）

Leader 的写权可达性检查第一版**零输出**（`lstrip("./")` 把 `.arcforge` 的点也剥了）。
dev 指出它险在**时机**：

> `exit 0 + 空输出` 长得像**一个干净的结论**，而它出现在**正为「这条检查跑得通」举证**的那一刻
> ⇒ 空输出会被读成「没有可查的对象」，然后**拿去支持一个正面主张**。

⇒ 它把这条接到了一条更早的记录上：

> 它与「**否定式断言在空集上平凡为真**」是同一件事的两种载体：
> **空集让否定式为真，空输出让主张无从证伪。**

**处方（采纳）**：**任何「零命中」结论，先喂一个已知命中的输入跑一遍，自证仪器打得出非零。**

⚠️ 一般形式：**报「没有命中」的检查，必须同时报「检查了多少个对象」。**

## 四十四、**当你无法中立时，把不中立与你为此设的约束一起公开**（test-m1c2-v1 提炼）

这却把凑判据的机会转移给了 Leader。**

Leader 的处置：**先声明自己不中立**，再**公开自己的约束**（只补维度、只消歧义、
凡放松一律不提），**并请对方据此审查**。

**验证者真的审了**：「两条修订都符合你的自我约束 —— M7 是纯加严且真的抓到东西，

> **当你无法中立时，把你的不中立和你为此设的约束一起公开，让对方能据以审查你
> —— 比声称中立强。**

⇒ **公开约束的价值不在于我会遵守它，在于它给了对方一把可以量我的尺子。**
若只说「我尽量中立」，对方**没有任何东西可以据以审查**。

## 三、各实例的教训（点名保留，因为它们的原文只在归档里）
